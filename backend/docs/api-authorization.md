# API authorization

Public routes are limited to `POST /api/auth/login`, `POST /api/auth/refresh`, `POST /api/auth/forgot-password`, `POST /api/auth/reset-password`, `POST /api/auth/telegram/webhook`, `POST /api/auth/challenges/**`, `POST /api/user-invitations/open`, `POST /api/user-invitations/accept`, `GET /api/auth/csrf`, `GET /api/auth/challenges/**`, and `GET /actuator/health` with its probe subpaths. Challenge requests are bound to the browser device cookie, and the webhook requires the configured Telegram secret. Other routes, including `/actuator/info`, require authentication. Internal error dispatches remain available to render failures. Missing, expired, invalid and revoked JWTs receive `401`.

Business modules can use `auth.api.ResourceAccessGuard` to enforce an allowed role together with an `OWNER`, `REGION` or `NETWORK` scope. The resource module must load ownership and region from trusted persistence and perform the check before returning data or making changes. Do not accept the resource scope from a request body or use a client-supplied owner/region to authorize access. Roles and region are checked against current user data, so a role change or account disablement takes effect on the next guarded request. A missing region never grants regional access. Denied access returns a generic `403 ACCESS_DENIED`, without resource attributes.

The guard provides shared enforcement, not a completed business permission matrix. Production object, task, contact and file endpoints must be wired to the approved action rules as those modules are implemented. Region checks currently compare exact region IDs; hierarchical and delegated access require the approved geographic rules. Field-level projections for limited object/contact access also belong to the resource modules. Director/CEO deletion, contract-approval scope, deadline approvals and other disputed actions remain pending customer approval. The guard grants no implicit administrator bypass and does not turn unknown permissions into access. Method security is enabled for additional endpoint/service restrictions.
