# Contacts API

API задачи T5833 работает поверх модели T5832. При отдельном выпуске веток
сначала применяется T5832. Интерфейс клиента и раскрытие телефонов сюда не входят.

| Метод | URL | Результат |
| --- | --- | --- |
| POST | `/api/contacts` | `201`, `{contact, duplicateContacts, warningCode}`, `Location` |
| GET | `/api/contacts/{id}` | `200`, карточка с доступными пользователю объектами |
| PATCH | `/api/contacts/{id}` | `200`, `{contact, duplicateContacts, warningCode}` |
| DELETE | `/api/contacts/{id}?version=0` | `204` либо `409` с запросом подтверждения |

Контракт: [OpenAPI](openapi/contacts.yaml). Аутентификация и CSRF совпадают с API
объектов: cookies `workflow_access_token`, `XSRF-TOKEN` и заголовок `X-XSRF-TOKEN` для записи.
Ответы CRUD запрещают кеширование. Ошибки используют общий `ApiError` проекта.

## Создание и изменение

POST принимает обязательные `name` (до 200 символов), `role` (до 100), хотя бы один
из `phone` и `email`, необязательные `comment` (до 2000), `contactTypeId`, `objectIds`
(до 100 разных UUID). Тип должен быть активным, все объекты должны быть доступны
пользователю. Автор и даты назначаются сервером. Неизвестные и защищённые поля,
неверные типы JSON, недопустимые UUID и значения возвращают `422` с `violations`.

Телефон проверяется libphonenumber и сохраняется в E.164. Пробелы, скобки,
дефисы, точки, невидимые знаки форматирования и префикс `00` нормализуются.
Национальные номера разбираются с `app.contacts.default-phone-region=UA`.
Добавочные номера не поддерживаются. Email обрезается по краям, проверяется
и приводится к нижнему регистру; предел — 254 символа.

PATCH требует текущую `version` и хотя бы одно изменяемое поле. Пропущенные поля
сохраняются, `null` очищает необязательное поле. Имя и роль очистить нельзя;
должен остаться телефон или email. `objectIds` через PATCH не меняется:
назначение контактов объектам выполняет API объектов. Если тип не передан,
сохраняется и ранее назначенный неактивный тип. Автор не меняется.
Повтор тех же значений не повышает версию и не добавляет событие истории.
Устаревшая версия возвращает `409 CONCURRENT_UPDATE` с `currentVersion`.

Совпадение телефона не блокирует запись. Ответ содержит
`warningCode: CONTACT_PHONE_DUPLICATE` и до 20 доступных активных контактов
с тем же номером: только `id`, `name`, `role`. Проверка учитывает старые
национальные номера. Недоступные и мягко удалённые контакты не раскрываются.

Телефон в карточке возвращается как `***` либо `null`; `normalizedPhone`
не возвращается. Это соответствует FR21. Раскрытие телефона и журнал раскрытий
предусмотрены отдельным сценарием. Email входит в карточку доступного контакта.

## Права

Роль, активность и регионы проверяются по базе при каждом обращении.
MANAGER видит контакты своих объектов в назначенных регионах; REGIONAL_MANAGER —
контакты объектов своих регионов и их дочерних регионов; DEVELOPMENT_DIRECTOR,
CEO и SUPERADMIN — по сети. CONTRACT_MANAGER видит только контакты объектов
в `CONTRACT_APPROVAL` или `CONTRACT_SIGNED`. Карточка не раскрывает связанные
объекты за пределами этого доступа. Недоступный контакт возвращает `404`.

Создавать могут MANAGER, REGIONAL_MANAGER, DEVELOPMENT_DIRECTOR и SUPERADMIN. Без привязки
контакт доступен своему автору из этих ролей и ролям с сетевым чтением.
CEO и CONTRACT_MANAGER через этот API только читают.
Существующий импорт объектов SUPERADMIN сохраняет отдельное разрешение.

За основу взята «Матриця дозволів: Контакт» из бизнес-требований v3,
размещённых в ресурсах KeySpace. «Власні» для менеджера трактуется как контакты
его объектов; для общей карточки достаточно одной доступной связи. Ограничение
удаления администратором применяется и к мягкому удалению T5833. Эти трактовки
нужно подтвердить при приёмке. Авторство не заменяет доступ к объекту.

| Роль | Создание | Редактирование | Мягкое удаление |
| --- | --- | --- | --- |
| MANAGER | Да | Контакты своих объектов в назначенных регионах | Нет |
| REGIONAL_MANAGER | Да | Контакты объектов своих регионов и подрегионов | Нет |
| DEVELOPMENT_DIRECTOR | Да | Контакты объектов по сети | Нет |
| SUPERADMIN | Да | Все, включая непривязанные | Да |
| CEO, CONTRACT_MANAGER | Нет | Нет | Нет |

Непривязанный контакт можно создать для последующего выбора в карточке объекта;
до привязки его данные меняет только SUPERADMIN. Для изменения общего контакта
достаточно одного доступного объекта: данные контакта общие для всех связей,
но ответ содержит только доступные объекты. Старые контакты без автора подчиняются
тем же правилам. `canEdit` и `canDelete` рассчитываются отдельно на сервере.
Изменение роли или назначений в БД действует уже при следующем запросе.

## Удаление и история

DELETE доступен только SUPERADMIN и требует текущую версию. При наличии хотя бы одного связанного объекта
с `object_statuses.is_final=false` первый запрос возвращает
`409 CONTACT_DELETION_CONFIRMATION_REQUIRED`, `currentVersion` и `confirmationToken`.
После явного подтверждения пользователя клиент повторяет DELETE с теми же
версией и `confirmationToken` в query. Токен связан с пользователем, контактом,
его версией, составом связей, версиями и статусами объектов. Изменение этого
состояния требует нового подтверждения. Объекты вне доступа не перечисляются.

Удаление устанавливает `deleted_at`, увеличивает версию и добавляет событие
`DELETED`. Строка контакта и `object_contacts` сохраняются. Повторный CRUD
возвращает `404`, выбрать удалённый контакт для объекта нельзя. Старые снимки
контактных данных в объектах остаются историческими снимками; в выдаче объектов
идентификатор активного контакта исключает удалённые записи.

Создание, изменение и удаление записываются в `contact_history` в той же
транзакции. Запись включает актёра, версию, время, действие, имена изменённых
полей и UUID связанных объектов. Для изменений сохраняются старое и новое значения
изменённых полей в `changed_values`: это бизнес-история в БД, недоступная через
CRUD API. Полные значения телефонов и содержимое истории не попадают в технические
логи приложения или ответы API. UUID объектов в истории сохраняются и после их
физического удаления. Ошибка журнала откатывает операцию. Создание контакта
через ручную карточку объекта и импорт также журналируется.

Изменения контакта и выбор существующего контакта сериализуются блокировкой
строки. Одновременные PATCH с одной версией дают один успешный ответ и один `409`.

## Миграция

`20261016_contact_crud` добавляет `deleted_at` и `contact_history`. Повторный
Liquibase update не добавляет таблицы, поля или записи повторно. Обратная SQL
миграция удаляет журнал и колонку, сохраняя контакты и связи. Перед откатом
нужно сохранить журнал: удаление колонки снимает отметки мягкого удаления,
и старая версия приложения снова увидит эти контакты.

`20261019_contact_audit_values` отдельно добавляет `changed_values`. Для старых событий
поле равно `{}`; повторное применение не меняет историю. Откат удаляет только эту
колонку и её ограничение, сохраняя контакты, связи и прежние поля журнала. Перед
откатом нужно сохранить значения истории. Применённые миграции T5832 и T5833 не изменены.
