# Хранение файлов в MinIO

Модуль `files` предоставляет `FileStorage` через `files::api`. Объекты и задачи
используют один сервис проверки содержимого, загрузки, сохранения метаданных
и выдачи подписанных ссылок. MinIO SDK остаётся в адаптере `integrations`.

## Владелец и ключ

`FileOwner.object(id)` и `FileOwner.task(id)` задаются сервером после проверки
доступа к соответствующей сущности. Имя файла не участвует в формировании ключа.

| Владелец | Настройка bucket | Ключ |
|---|---|---|
| Объект | FILE_BUCKET, по умолчанию workflow-files | objects/{objectId}/{fileId} |
| Задача | TASK_FILE_BUCKET, по умолчанию workflow-task-files | tasks/{taskId}/{fileId} |

UUID файла генерируется сервером. Даже при одинаковых именах параллельные
загрузки имеют разные ключи. Старые файлы читаются по сохранённым bucket и
storage_key; новые настройки и формат ключа их не перемещают.

## Подключение модуля

Вызывающий сервис получает пользователя из сессии, проверяет текущие права,
категорию и состояние сущности. В своей транзакции он блокирует владельца,
чтобы перепривязка или удаление не изменили права во время записи.
Затем вызывает общий API:

```java
files.upload(FileOwner.task(taskId), actorId, categoryId, name, input,
        stored -> history.recordFileUpload(taskId, actorId, stored.id()));
```

Callback вызывается после записи метаданных, внутри той же транзакции. История
или другое обязательное действие публикуется там; внешние сообщения отправляются
через outbox после commit. Ошибка callback откатывает метаданные и историю.
Вызывающий код закрывает входной поток. В HTTP-ответ попадает DTO модуля, а не
`StoredFile`: bucket и key являются внутренними данными хранения.

`download(owner,fileId)` вызывается только после проверки прав чтения, в том
числе ограничений категории. Он проверяет принадлежность владельцу и deleted_at,
доступность MinIO и наличие байтов. Чужой или удалённый fileId даёт 404. Метод
возвращает URL и expiresAt; сам URL не используется как постоянный идентификатор.
REST-методы файлов задач подключаются в Epic Tasks; общий сервис уже поддерживает
их владельца и метаданные без дополнительной реализации загрузки.

## Ограничения и ошибки

FILE_MAX_SIZE_BYTES по умолчанию 20971520, допустимы значения от 1 до 20971520.
FILE_ALLOWED_EXTENSIONS по T5781: jpg,png,heic,pdf,docx,xlsx,dwg. Проверяются сигнатуры
содержимого, для docx/xlsx — ZIP и обязательные элементы соответствующего типа.
Расширение и HTTP Content-Type не являются доказательством формата. Размер
читается с верхней границей; ZIP ограничен по числу записей и объёму распаковки.
Проверка типа не заменяет антивирус. HEIC принимается по умолчанию с проверкой
ftyp и HEIC-брендов контейнера; сохранённый MIME-тип — image/heic. Настройка
FILE_ALLOWED_EXTENSIONS заменяет список целиком: чтобы отключить HEIC, исключите
heic из значения. В существующем окружении с явно заданным старым списком
нужно добавить heic в FILE_ALLOWED_EXTENSIONS при обновлении.

Пустое содержимое, недопустимое имя, превышение прикладного лимита и подмена
расширения дают 422 с полем file. Ограничения multipart контейнера: 20 МиБ для
файла и 21 МиБ для запроса; раннее отклонение контейнером даёт 413.

Перед записью байтов создаётся долговечное резервирование ключа в отдельной
транзакции. Метаданные сохраняются только после успешного ответа MinIO.
При ошибке MinIO файл отсутствует в БД, а резервирование остаётся для очистки.
Если байты записались, но ответ потерялся, либо откатилась история, очистка
удаляет все версии ключа через десять минут и повторяет операцию при сбое.
Успешные и заблокированные активной загрузкой ключи не очищаются.

BinaryStorageException обрабатывается для всех REST-потребителей: 503,
STORAGE_UNAVAILABLE, сообщение File storage is unavailable и correlationId.
Параметры соединения и внутреннее исключение не выдаются клиенту.

## Доступ к MinIO

Bucket закрыт для анонимного доступа. Новый bucket создаётся без публичной
policy. Перед загрузкой и выдачей ссылки сервис проверяет policy; разрешение
анонимному Principal блокирует операцию. Чужая policy не изменяется автоматически.
Учётной записи приложения нужны проверка и создание bucket, чтение policy,
запись, stat и чтение объектов, удаление всех версий для очистки.

Скачивание выполняется по presigned GET. FILE_LINK_TTL по умолчанию 5m,
диапазон 1s–15m. Подпись задаёт attachment и application/octet-stream.
После истечения срока MinIO отклоняет ссылку. Мягкое удаление прекращает выдачу
новых ссылок; ранее выданная подпись остаётся действительной до своего срока.

MINIO_ENDPOINT используется для запросов приложения, MINIO_PUBLIC_ENDPOINT —
для адреса в подписи, MINIO_REGION по умолчанию us-east-1. На стенде публичный
endpoint должен быть доступен браузеру по HTTPS. Прокси сохраняет подписанные
Host, путь и query. Отдельный endpoint не требует публичной bucket policy.
Lifecycle AbortIncompleteMultipartUpload настраивается инфраструктурой для
очистки частей S3 при завершении процесса посреди multipart-загрузки.

Физическое удаление объекта очищает файлы обоих типов владельцев через
сохранённые метаданные. Мягкое удаление файла сохраняет байты до удаления объекта.
Существующая схема files уже содержит object_id и task_id; новая миграция для
этого сервиса не требуется.
