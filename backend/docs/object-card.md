# Карточка объекта

T5774. Источник: 12 критериев карточки с правками от 12.10 и 21.10.2026, сверенные 22.10.2026, правила T5775, PRD BRL-04/11, FR-04/05/13/14/93/94 и таблица переходов T6712. Реализован backend-контракт; интерфейс карточки и запись полей относятся к отдельным задачам.

`GET /api/objects/{id}` требует действующей сессии. Ответ содержит `Cache-Control: no-store`. Роль, активность и регион берутся из базы при каждом запросе. GET не меняет объект, задачи, согласования или историю; данные читаются в одной транзакции REPEATABLE READ.

## Видимость

| Пользователь | Состав |
| --- | --- |
| Менеджер объекта в своём регионе | Полные данные |
| Провідний в явно назначенных регионах | Полные данные |
| Директор з розвитку и CEO | Полные данные по всей сети |
| Адміністратор | Полные данные по всей сети, включая тип договора |
| Погодження договорів | По всей сети: название, координаты, технический блок и описание, тип договора, даты подписания основного и предварительного договора, ввод в эксплуатацию, плановая и фактическая даты акта приймання на БМР, плановая дата открытия и метаданные действий |
| Пользователь раздела без полного просмотра объекта | Ровно `name` и `entrance`, без версии, ID, статуса, контактов, запросов и коммерческих данных |

Урезанный ответ применяется и при прямом запросе объекта за пределами региона. Неподтверждённые запросы и переходы не раскрываются в таком ответе. Пользователь без прав на раздел или неактивный пользователь получает 403 до поиска объекта. Отсутствующий, в том числе физически удалённый объект — 404; некорректный UUID — 400; отсутствие сессии — 401.

Полная карточка сохраняет поля контракта создания, включая nullable `shortComment` до 200 символов и структурированные `technicalSpecifications` и `commercialTerms`. В `workflow` находятся ІК, причина отказа, предыдущие статусы, тип договора и `milestones` с плановыми и фактическими датами. Телефон маскируется как `***`; раскрытие защищённых контактов выполняется отдельно с аудитом. Google Maps формируется из текущих координат.

Тип договора возвращается менеджеру объекта, провідному в своих регионах, директору, CEO, Погодження договорів и Адміністратору. В полной карточке это `workflow.contractType` и `workflow.contractTypeId`: пустые значения не сериализуются, историческое значение без ссылки на справочник сохраняется. Возможность исправить тип договора после создания задач определяется отдельно по T5775.

В ограниченной карточке Погодження договорів рядом с `contractSignedDate` находятся `preliminaryContractSignedDate`, `commissioningDate`, `constructionAcceptancePlannedDate`, `constructionAcceptanceActualDate` и `openingPlannedDate`. Даты возвращаются в формате YYYY-MM-DD или как null, если не заполнены. Фактическая дата открытия, даты акта для оплат, короткий комментарий, коммерческий блок, адрес, контакты и полный `workflow` в этот ответ не включаются. Полные карточки сохраняют даты в `workflow.milestones`.

## Действия

`availableTransitions` содержит ID и код правила, код и название целевого статуса, `confirmationRequired`, `confirmingRoleId`, массивы `requiredFields` и `requiredCompletedTaskCodes`, действие `unfinishedTaskAction` и блок `unmetConditions`.

Данные берутся из активных переходов и активных целевых статусов. Системные переходы, чужие роли и правила с неприменимым условием предыдущего статуса исключаются. Незаполненные обязательные поля и незавершённые обязательные задачи не скрывают разрешённый переход: они возвращаются в `unmetConditions`. Используется та же проверка условий, что и при записи статуса; учитывается создание задач в прошлом, включая завершённые. Неоднозначно настроенные переходы в один целевой статус не предлагаются. Поля, причины, незавершённые задачи и превью шаблона дополнительно проверяются при выполнении перехода.

`unmetConditions` всегда содержит три массива:

| Поле | Состав |
| --- | --- |
| `missingFields` | Имена незаполненных обязательных полей; неактивный тип договора считается недоступным. При отказе `refusalReasonId` требуется передать заново, историческая причина не подставляется |
| `incompleteTasks` | Реальные задачи: `id`, стабильный `code` элемента шаблона, текущее `name` и `status`; все статусы кроме DONE считаются незавершёнными |
| `missingTaskCodes` | Коды обязательных элементов, для которых задача ещё не создана |

Поля проверяются общей функцией карточки и записи перехода. Для задач используется один запрос на карточку по объединению обязательных кодов доступных правил. Для каждого кода выбирается последний набор, содержащий этот элемент, включая отменённые наборы. Более новый набор без элемента не скрывает предыдущий. Условие выполняет только DONE; отменённая или отсутствующая задача остаётся препятствием. Прежние задачи учитываются для кода, по которому ещё нет набора. Ручные задачи по совпадению названия не учитываются.

GET читает условия без блокировки задач и без изменений данных. При записи те же задачи повторно проверяются под блокировкой: карточка описывает состояние своего снимка, но не гарантирует последующий переход.

`pendingRequests` содержит только PENDING, в порядке времени и UUID:

| Поле | Значение |
| --- | --- |
| `id`, `type` | UUID запроса; STATUS или ENTRY_POINT |
| `requested.status` | Целевой статус для STATUS, иначе null |
| `requested.entrance` | Новые координаты для ENTRY_POINT, иначе null |
| `initiatorId` | Инициатор |
| `confirmingRoleId` | Роль согласующего, если решение принимает роль |
| `confirmingUserId` | Конкретный согласующий, если решение принимает пользователь |
| `requestedAt` | Время создания из базы |

Исходная сериализованная команда, токены и служебная версия запроса не возвращаются. Согласования статуса читаются из действующего хранилища T6712 через публичный API Approvals. Для точки входа добавлено хранилище `entry_point_approval_requests` с уникальным ожидающим запросом по объекту и ровно одним способом назначения согласующего. Создание, подтверждение и применение изменения точки — отдельный сценарий T5775; здесь реализовано чтение сохранённого запроса, без изменения текущей точки.

## Редактируемые поля

`editableFields` — карта имён полей и boolean для обычного PATCH по правилам T5775. Неизвестный или отсутствующий ключ считается закрытым. Это описание разрешений, а не замена серверной проверки записи.

Тип договора блокируется для всех, кроме Адміністратора, после набора из привязанного к типу договора шаблона; общие наборы и ручные задачи его не блокируют. Используется сохранённая версия шаблона. `commissioningDate` недоступна менеджеру, `shortComment` следует общим правам объекта. Плановая дата открытия всегда только для чтения.

Менеджер редактирует свой объект, провідний — объекты своих регионов, директор и Адміністратор — всю сеть. CEO только читает. Адрес и тип объекта доступны по общим правам на любом этапе. Для изменения точки входа при паузе и отказе учитывается предыдущий этап.

Погодження договорів редактирует тип договора, даты подписания основного и предварительного договора, дату ввода в эксплуатацию, плановую и фактическую даты акта БМР. Системные поля, Google Maps, плановая дата открытия, статус и координаты закрыты; координаты и статус меняются отдельными действиями. Перепривязка менеджера/региона не относится к обычному редактированию.

Версия объекта возвращается в полном и техническом ответах для optimistic locking. Проверка версии и применение PATCH выполняются в задаче редактирования.

## Миграция

`20261007-entry-point-approval-requests` добавляет одну таблицу и пять индексов. Старые миграции и записи не изменяются. Rollback удаляет только новое хранилище; перед откатом среды с действующими запросами их следует сохранить. Контракт API: [OpenAPI](openapi/objects.yaml).
