# Комментарии объекта

T5780, PRD FR-99. Контракт относится к backend; отображение ленты в клиенте
в этой задаче не меняется.

## API

| Метод | URL | Результат |
|---|---|---|
| GET | `/api/objects/{id}/comments` | 200, `items`, `nextCursor`, `hasMore` |
| POST | `/api/objects/{id}/comments` | 201, созданный комментарий и Location |
| PATCH | `/api/objects/{id}/comments/{commentId}` | 200, обновлённый комментарий |
| DELETE | `/api/objects/{id}/comments/{commentId}` | 204 |

POST принимает `{"text":"Текст комментария"}` и необязательный массив `mentions`.
PATCH принимает `{"text":"Новый текст","version":0}`. Версия относится к
комментарию, берётся из ответа POST, PATCH или GET. При устаревшей версии —
409 с `currentVersion`; ранее сохранённый текст остаётся. Повтор того же
текста с актуальной версией не меняет время, версию и историю.

Ответ содержит `id`, `author: {id,name}`, `text`, `createdAt`, `editedAt`,
`edited`, `editLabel`, `version`, `mentions`. Автор — текущий пользователь из сессии;
имя берётся из реестра пользователей. Время — ISO 8601 UTC. После изменения
`edited=true`, `editedAt` заполнено, `editLabel="відредаговано"`.
До изменения `editedAt` и `editLabel` равны null.

Текст сохраняется как обычный текст, с исходными переносами и пробелами.
Клиент должен выводить его текстом, без интерпретации HTML. Нужен хотя бы
один видимый символ; лимит — 1000 Unicode code points, включая пробелы и
переносы. Пустой текст, превышение лимита, NUL и некорректные суррогатные
пары — 422 с полем `text`; превышение сообщает лимит 1000. Неизвестные поля,
попытка передать автора/время и некорректная версия также возвращают 422.

## Упоминания

В POST и PATCH можно передать выбранных пользователей и расположение их
`@Имя` в обычном тексте. ID определяет получателя независимо от совпадения имён.
`offset` и `length` измеряются в UTF-16 code units, как индексы строк JavaScript.
Диапазоны не пересекаются; фрагмент должен совпадать с `@` и текущим полным именем.

```json
{
  "text": "@Іван Петренко перевірте об'єкт",
  "mentions": [{"userId": "a0000000-0000-0000-0000-000000000001", "offset": 0, "length": 14}]
}
```

Общий лимит текста остаётся 1000 Unicode code points;
служебные ID и диапазоны не входят в этот лимит. Несуществующий, неактивный
пользователь или отсутствие права читать комментарии объекта — 422 с полем
`mentions`, без сохранения комментария и уведомлений. Минимальная карточка
чужого объекта не даёт доступа к его комментариям. CEO и Адміністратор могут
получать упоминания, но не создавать комментарии.

Упоминания сохраняются и возвращаются в ленте и истории. Отсутствие `mentions`
равнозначно пустому массиву; при PATCH это удаляет прежние привязки. Обычный
текст с `@`, включая email, не создаёт уведомлений без выбранного пользователя.
Изменение только привязок тоже повышает версию и ставит отметку редактирования.

Существующий модуль Notifications получает `COMMENT_MENTIONED` с `objectId`;
`GET /api/notifications` возвращает также `objectUrl` — ссылку на карточку API
`/api/objects/{id}`. Контракт backend позволяет клиенту открыть карточку по ID.
Самоупоминание не уведомляет. Повторы одного пользователя в одном комментарии
дают одно уведомление; при редактировании уведомляются только добавленные
получатели. После удаления и нового добавления упоминания создаётся новое
уведомление. Неизменённый текст и набор привязок не создают запись или уведомление.

Комментарий, упоминания, история и очередь уведомлений фиксируются одной
транзакцией. Ошибка любой записи откатывает всё изменение. Перед каждым
созданием и редактированием права получателей проверяются заново; ссылка не
обходит текущую авторизацию при открытии объекта. Подключение списка выбора
и отображение упоминаний в клиенте относятся к frontend.

## Права

| Роль | Просмотр | Создание |
|---|---|---|
| MANAGER | Собственные объекты в своём регионе | Там же |
| REGIONAL_MANAGER | Явно назначенные регионы | Там же |
| DEVELOPMENT_DIRECTOR | Вся сеть | Вся сеть |
| CONTRACT_MANAGER | Вся сеть, независимо от статуса | Вся сеть |
| CEO, SUPERADMIN | Вся сеть | 403 |

Права полного просмотра используются из BRL-11. Исключение для
CONTRACT_MANAGER относится только к комментариям T5780 и не расширяет
карточку или историю объекта. Минимальный просмотр чужого объекта не даёт
доступа к комментариям.

Редактирование и удаление доступны только автору при сохранённом праве
добавления комментариев к этому объекту. После перепривязки объекта,
деактивации пользователя или перехода автора в роль CEO/SUPERADMIN запись
не даёт прежних прав. Чужой автор — 403. Комментарий другого объекта или
несуществующий комментарий — 404; физически удалённый объект — 404.

Cookie-сессия обязательна. POST/PATCH/DELETE требуют существующий CSRF
заголовок. Ответы имеют `Cache-Control: no-store`. Права и активность читаются
из БД, а не из старой роли в JWT; при записи блокируются пользователь и
объект, затем повторно проверяется текущая область доступа.

## Пагинация

Порядок — от старых записей к новым по `sequence`. `limit` по умолчанию 50,
допустимы 1–100. `cursor` передаётся без изменений из `nextCursor` предыдущей
страницы того же объекта. На первой странице фиксируется верхняя граница
последовательности: новые комментарии видны при новом чтении ленты.
Редактирование не меняет позицию; удаление строки, на которой закончилась
страница, не ломает продолжение. Права проверяются на каждой странице.

Запрос использует индекс `(object_id,sequence)` и читает максимум `limit+1`
строк, без OFFSET и полного COUNT. Курсор не является разрешением на доступ.
Некорректный или чужой курсор и диапазон limit — 422; неверный тип limit — 400.

## Транзакции, история и удаление объекта

Создание, изменение и удаление записывают `COMMENT_CREATED`, `COMMENT_EDITED`,
`COMMENT_DELETED` с автором и прежним/новым комментарием в историю объекта.
История и запись комментария выполняются в одной транзакции PostgreSQL.
Ошибка истории откатывает текст, метаданные и удаление. Версия объекта не
повышается; текущие запросы согласования не становятся устаревшими.

Во время удаления объекта T6797 все методы возвращают 409. Защита действует
в HTTP, сервисе и БД. После завершения комментарии удалены каскадно, а их
полные записи и события истории остаются в снимке Audit Log.

## Миграция

`20261008-object-comments` добавляет последовательность, индекс и дату
редактирования к существующей таблице. Прежние записи упорядочиваются по
`created_at,id`; текст, автор, время создания и версия сохраняются.
Изменённые старые записи получают `edited_at=updated_at`.

Перед обновлением нужно завершить операции удаления PENDING: миграция
останавливается при незавершённых удалениях, чтобы не менять замороженные
записи. PostgreSQL выполняет changeset транзакционно. Rollback удаляет
только новые метаданные/индексы/триггер; комментарии, текст, версии и
исходные даты сохраняются. Повторное применение восстанавливает метаданные.

`20261015-object-comment-mentions` добавляет JSONB-метаданные упоминаний к
комментариям и учитывает их в триггере версии и отметки редактирования. Старые
тексты, авторы, время и версии не меняются; их список упоминаний пуст.
Миграция останавливается при PENDING-удалениях объекта. Rollback удаляет
метаданные упоминаний и возвращает прежнее правило триггера, сохраняя текст,
автора и существующие даты и версии. Повторное применение не дублирует данные.
