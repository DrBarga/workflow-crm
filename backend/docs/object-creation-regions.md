# Регионы и источник при создании объекта

Доработка T5771 по пяти дополнительным критериям от 13.10.2026. Контракт POST описан в [OpenAPI](openapi/objects.yaml); прежние поля и сценарий импорта сохранены.

## Назначенные регионы

Все назначения регионов хранятся в `user_regions(user_id, region_id)`, с UUID, FK, уникальной парой, временем создания и изменения и версией. Отдельного основного региона в users нет. Справочник регионов плоский: доступ даёт только явное назначение. Публичная проекция Users читает действующие назначения из БД. Миграция прежних назначений и откат описаны в [модели регионов](user-region-model.md).

Менеджер создаёт объект только в назначенном регионе и только на себя. Региональный выбирает активного менеджера своего региона. Директор по развитию может работать без персонального региона и создать объект в любом регионе, назначив менеджера с основным или дополнительным назначением в выбранном регионе. Неактивный, неизвестный пользователь, другая роль и менеджер без назначения возвращают 403; отсутствие managerId у регионального или директора — 422.

Справочник пользователей и управление назначениями остаются ответственностью Users. Эта доработка добавляет хранение и использование назначений в создании объектов; отдельного интерфейса управления пользователями не добавляет.

## Загруженные границы

`region_boundaries` содержит одну GeoJSON-геометрию на регион. Формат geometry — Polygon или MultiPolygon в WGS84, порядок координат `[longitude, latitude]`. Кольца замкнуты, минимум четыре точки; первое кольцо внешнее, следующие — отверстия. Feature/FeatureCollection нужно преобразовать к геометрии перед загрузкой. Пример:

```json
{"type":"Polygon","coordinates":[[[30,50],[31,50],[31,51],[30,51],[30,50]]]}
```

Ни один рабочий регион не получает выдуманную границу при миграции. Если regionId не передан, точка проверяется по загруженным границам. Автоматическое значение используется только при одном совпадении. Неизвестная, некорректная, отсутствующая или неоднозначная граница требует ручного выбора с 422; на общей границе двух полигонов действует то же правило. У вручную выбранного региона есть приоритет. Независимая проверка принадлежности точки Украине остаётся обязательной.

Геокодер по-прежнему заполняет адрес. Его текстовая подсказка области не определяет регион CRM. При явно очищенных названии и адресе запрос отклоняется до геокодирования; при отсутствии обоих полей сохраняется прежнее автозаполнение.

Для административного импорта T5785 сохранён прежний контракт: пропущенный регион сопоставляется по подсказке геокодера. Новое правило загруженных границ относится к ручному POST создания; импорт не требует изменения существующих файлов.

## Источник и повторные запросы

`dataSourceId` ссылается на активное значение справочника T5770. Пропуск/null сохраняет null; неизвестный UUID, неверный тип и неактивное значение дают 422 с полем dataSourceId. Источник сохраняется той же транзакцией, что объект, контакт, ключ и журнал.

Для запросов без источника fingerprint остаётся прежним. Изменение источника с прежним ключом даёт 409. Повтор возвращает сохранённый UUID, даже если справочник позднее деактивирован; новый объект с таким значением создать нельзя. Повтор заново проверяет роль, активность и назначение пользователя в регион объекта.

Директор видит полные сведения о дублях по всей сети. Менеджер видит свой дубль и в дополнительном регионе; сведения чужих объектов по-прежнему ограничены. Подтверждение дубля и отмена записываются существующим механизмом аудита.

## Миграция и откат

Новый changeset `20261013_user_regions` создаёт две таблицы после миграций T5770. Основные назначения, объекты и справочники не переписываются; повторное применение не дублирует строки. Rollback удаляет только новые дополнительные назначения и загруженные границы; основной регион пользователя сохраняется. Перед downgrade рабочей базы новые назначения и границы нужно сохранить отдельно.

Интеграционные тесты проверяют права, несколько регионов, текущие разрешения на повторе, геометрию, ручной выбор, источник, ограничения БД, откат и совместимость с прежними сценариями создания.
