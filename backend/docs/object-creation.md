# Создание объекта (T5771)

`POST /api/objects` создаёт объект в статусе `FOUND` («Знайдено») и возвращает `201`, заголовок `Location` и сохранённые поля. Контракт для импорта в Swagger Editor: [openapi/objects.yaml](openapi/objects.yaml).

Перед записью выполняется [проверка дублей](object-duplicates.md). При совпадениях ответ `409 DUPLICATES_FOUND`; явное подтверждение `confirmDuplicates: true` позволяет создать объект с записью решения в журнал и историю. Отмену можно записать через `POST /api/objects/duplicate-cancellations`.

Нужны cookie действующей сессии, `X-XSRF-TOKEN` и `Idempotency-Key`. Ключ формируется один раз при начале отправки формы и сохраняется при повторе после сетевой ошибки. Для новой формы нужен новый ключ.

## Тело запроса

```json
{
  "name": "Приміщення на Хрещатику",
  "objectType": "BUILT_IN_PREMISES",
  "address": "Адреса, уточнена менеджером",
  "regionId": "00000000-0000-0000-0000-000000000001",
  "entrance": {"longitude": 30.5234, "latitude": 50.4501},
  "objectArea": 120.5,
  "landArea": null,
  "contact": {
    "name": "Власник",
    "role": "Власник",
    "phone": "+380671234567",
    "email": null
  }
}
```

В примере замените `regionId` на действующий UUID из справочника CRM.

- Обязательны `entrance.longitude`, `entrance.latitude` и хотя бы одна положительная площадь. Координаты WGS84, максимум 7 знаков после запятой, площади — 2 знака.
- Название необязательно в запросе, но всегда заполнено после создания. Если его нет, оно null, пустое или пробельное, используется итоговый адрес объекта: ручная поправка адреса либо результат геокодирования. Непустое ручное название сохраняется. Внешние пробелы удаляются; неразрывные пробелы нормализуются. Максимальная длина названия и адреса — 500 символов. Тип пока необязателен.
- Если клиент явно передал пустые/null название и адрес, либо очистил одно поле при отсутствии второго, ответ `422 name`: «Fill in the object name or address», до геокодирования. Когда оба поля отсутствуют, сохраняется автозаполнение из геокодера. Пустой результат также даёт `422 name`. Ошибка доступности геокодера остаётся `503`.
- Тип задаётся кодом активного справочника: `LAND_PLOT`, `BUILT_IN_PREMISES`, `SHOPPING_CENTER`, `HANGAR`; прежний `RESIDENTIAL_GROUND_FLOOR` сохранён только для исторических объектов.
- Контакт можно не передавать до Epic Contacts. Для нового контакта передайте `contact`: имя, роль и телефон либо email. Телефон нормализуется к E.164, email — к нижнему регистру. Создаются запись в `contacts` и связь с объектом; в ответе возвращается `contactId`.
- Для существующего контакта передайте `contactId` вместо `contact`. Эти два варианта нельзя передавать одновременно: `422 contactId`. Несуществующий и недоступный контакт дают одинаковую ошибку `422 contactId`, без раскрытия его данных. Менеджер может использовать контакт своего объекта в своём регионе, региональный — контакт любого объекта своего региона. Ссылка возвращается в `contactId`, поле `contact` равно null; телефон и email выбранного контакта в этом сценарии не раскрываются.
- Менеджеру объект назначается на него самого; `managerId` можно не передать либо указать собственный UUID. Региональный (`REGIONAL_MANAGER`) и директор по развитию (`DEVELOPMENT_DIRECTOR`) выбирают активного менеджера, назначенного в регион объекта.
- `dataSourceId` — необязательный UUID активного значения справочника «Джерело». Пропуск и null равнозначны; неизвестное или неактивное значение возвращает `422 dataSourceId`. Выбранный UUID возвращается в ответе и сохраняется при повторе запроса.
- Статус, автор, даты, версия и ссылка Google Maps из запроса не принимаются. Неизвестные поля, включая вложенные, возвращают `422` с путём поля в `violations`. Технический и коммерческий блоки принимаются в формате ниже.
- Менеджер создаёт только в одном из своих назначенных регионов; региональный — в своём регионе. Директор по развитию создаёт в любом регионе с назначением подходящего менеджера. CEO, CONTRACT_MANAGER и SUPERADMIN не получают разрешение на ручное создание.

## Адрес и регион

Если адрес отсутствует, backend выполняет обратное геокодирование по точке входа. Регион определяется отдельно по загруженным границам. Переданные вручную значения имеют приоритет независимо друг от друга. Название объекта геокодер не меняет.

Адаптер использует Nominatim JSON API. `GEOCODING_URL` позволяет заменить провайдера на совместимый внутренний сервис без изменения кода. `GEOCODING_USER_AGENT` идентифицирует приложение.

Для локального окружения в `.env.example` указан публичный сервер. Его [правила использования](https://operations.osmfoundation.org/policies/nominatim/) ограничивают приложение одним запросом в секунду. Redis ограничивает суммарную частоту экземпляров backend и хранит результаты 7 дней. Адреса относятся к данным [OpenStreetMap contributors](https://www.openstreetmap.org/copyright). Во фронтенде рядом с полученными адресами требуется эта атрибуция. Публичный сервис не используется для автодополнения или массового импорта.

Для конфиденциальных объектов требуется внутренний Nominatim либо согласованный провайдер: координаты передаются сервису, указанному в `GEOCODING_URL`. За пределами локального окружения автоматический публичный endpoint не включается; его нужно задать явно.

Регион CRM определяется по точке входа только при наличии подходящего Polygon/MultiPolygon в `region_boundaries`. При отсутствии границ, несовпадении, некорректной геометрии или пересечении нескольких регионов backend возвращает `422 regionId` с просьбой ручного выбора. Подсказки области из геокодера не заменяют загруженную границу. Ручной `regionId` имеет приоритет; регион текущего пользователя не подставляется. [Назначения нескольких регионов и формат границ](object-creation-regions.md).

Независимо от геокодирования точка проверяется локально по [границе Украины](../src/main/resources/geography/README.md), включая Крым. Точка в соседней стране отклоняется даже внутри общего прямоугольника координат Украины.

Недоступность провайдера, исчерпание лимита или отсутствие результата дают `503`. Объект и запись ключа не сохраняются; можно повторить запрос либо заполнить адрес и регион вручную.

## Повторные запросы и журнал

Ключ ограничен 128 ASCII-символами: буквы, цифры, `.`, `_`, `:`, `-`. Область ключа — пользователь. Один ключ с тем же нормализованным запросом возвращает тот же объект с `201`; другое содержимое даёт `409`. Параллельные запросы сериализуются транзакционной блокировкой PostgreSQL. Уникальность пользователя и ключа закреплена ограничением базы.

Отсутствующий или пустой ключ даёт `422` до создания. Объект, новый контакт, связь, ключ и запись `CREATED` в `object_history` сохраняются одной транзакцией. Ошибка любой части откатывает весь сценарий. Повтор запроса не создаёт контактов, связей или записей журнала. На повторе снова проверяются действующая роль и регион пользователя. ID выбранного контакта записан в `object_creation_requests`: ответ стабилен, даже если позднее к объекту добавляются другие контакты. Запросы без `contactId` сохраняют прежний отпечаток тела.

## Миграция и откат

Новый changeset `20261001_object_creation` делает контакт необязательным и создаёт `object_creation_requests`. Опубликованные changeset T5770 не изменены.

Доработка 03.10.2026 добавляет changeset `20261002_object_contacts`: таблицы `contacts` и `object_contacts`, внешний ключ выбранного контакта в запросе создания и индексы. Старые вложенные контакты копируются по одному на объект, без предположений об одинаковых людях. Их поля и прежние объекты не изменяются. Поле `objects.name` остаётся nullable для исторических записей; новые объекты всегда получают название до сохранения.

Откат доработки возвращает прежнюю схему. Для объектов, созданных по ссылке на контакт, данные выбранного контакта сначала сохраняются в прежних полях объекта. Контакты и связи как отдельный реестр удаляются: перед рабочим downgrade нужна резервная копия. Повторное update не дублирует записи. Модуль `contacts` подключён через публичный контракт; его инфраструктура читает только проекцию доступа связанного объекта. Полный реестр, редактирование и раскрытие телефонов остаются задачами Epic Contacts.

Откат удаляет таблицу ключей и возвращает прежние ограничения контакта. Если после обновления созданы объекты без контакта, сначала нужно заполнить их контакты: предыдущая схема не допускает таких записей. Откат в этом случае завершается ошибкой и сохраняет данные, не подставляя фиктивные контакты и не удаляя объекты.

Проверки: API, региональные права, 422 по полям, граница, сбой геокодера, JWT/CSRF/CORS, повторные и конкурентные запросы, атомарность журнала, обновление/откат/повтор миграции. Команда: `mvn -Pintegration verify` на Java 21 с Docker для Testcontainers.

## Технический и коммерческий блоки (05.10.2026)

`technicalSpecifications` и `commercialTerms` — необязательные JSON-объекты. Каждый их элемент также необязателен; пропуски и null не заполняются нулями. Нельзя передавать блоки строками, массивами, неизвестные вложенные поля, числа строками или порядковые номера enum. Ошибки возвращаются с полным путём, например `commercialTerms.fixedRentAmount`.

```json
{
  "technicalSpecifications": {
    "buildingArea": 200.5, "firstFloorArea": 110.5, "secondFloorArea": 90,
    "basementArea": 30.25, "salesHallArea": 80.75, "floorSlabHeight": 3.8,
    "connectedPower": 100.25, "waterSupplyFlow": 2.5,
    "powerConnectionCategory": "II", "sewageType": "LOCAL_TREATMENT"
  },
  "commercialTerms": {
    "leaseTerms": "Оренда на 5 років", "fixedRentAmount": 45000.25,
    "rentIndexationPercent": 10.5, "turnoverPaymentPercent": 7.25,
    "counterpartyTaxStatus": "COMPANY_VAT", "constructionTermDays": 90,
    "contractDurationYears": 5.5
  }
}
```

Названия, единицы измерения и справочные значения приведены в [object-fields.md](object-fields.md). Все числа неотрицательны; дробные значения допускают до двух значащих знаков после запятой. Сумма фиксированной аренды передаётся в гривнах без НДС, как в критериях модели; расчёты используют BigDecimal. Доплата от ТО — от 0 до 100 процентов. Индексация null означает отсутствие, 0 — явно заданный ноль. Срок БМР — целое число дней, срок договора — годы, допускаются дробные значения. Условия аренды — до 5000 символов. API не принимает тип договора, даты и поля решения ІК в создании: они относятся к другим сценариям.

В ответе возвращаются сохранённые блоки и `googleMapsUrl`, вычисляемая из координат WGS84. Ссылка не хранится отдельно в БД и не вызывает запрос Google Maps. Она и поля блоков доступны также при повторе с тем же ключом. Значения новых блоков участвуют в отпечатке запроса; отсутствующие/null блоки сохраняют прежний отпечаток без блоков. Флаг подтверждения дублей по-прежнему исключён из отпечатка.

Создание блоков, объекта, контакта, истории и ключа выполняется в существующей транзакции. Ни блоки, ни вычисляемая ссылка не меняют региональные права.

Добавлен changeset `20261005-object-creation-name`: поле name расширено до 500 символов для полного адреса. Зависимая вычисляемая колонка поиска дублей и её индекс пересоздаются в той же транзакции. Старые значения, UUID и версии не изменяются. Откат возвращает 250; проверка длины перед изменением блокирует откат при более длинных названиях без обрезки данных. Перед таким downgrade нужно отдельно сохранить длинные значения и согласовать их сокращение. Повторное применение не создаёт новых справочных записей.
