# Физическое удаление объекта

DELETE `/api/objects/{id}` доступен только действующему Адміністратору
(SUPERADMIN). Роль проверяется в базе; JWT не заменяет проверку активности.
Для cookie-запроса нужен X-XSRF-TOKEN. Остальные роли получают 403;
отсутствующий объект и повтор после завершения удаления — 404.

## API и порядок выполнения

Ответ 202 содержит постоянный ID операции и Location
`/api/object-deletions/{operationId}`. GET по этому адресу доступен только
администратору и возвращает PENDING или COMPLETED, число попыток, безопасный
код последней ошибки, время принятия и завершения. Оба ответа имеют
Cache-Control: no-store. Повторный DELETE во время PENDING возвращает ту же
операцию, не создавая вторую.

Принятие блокирует строку объекта, повышает его версию и сохраняет операцию
с перечнем всех файлов. Файлы включают вложения задач и записи deleted_at.
Повышение версии защищает от записи через ранее открытые транзакции.
Объект скрывается из списка; его карточка, история, согласования и изменение
через `/api/objects/{id}/...` возвращают 409. Триггеры PostgreSQL блокируют
изменение объекта, задач, вложений, комментариев, связей контактов и запросов
до завершения операции. Перенос связанной записи на другой объект также
запрещён. Проверка дублей продолжает учитывать ожидающий удаления объект.

Обработчик берёт одну операцию через FOR UPDATE SKIP LOCKED. Затем удаляет
в MinIO все версии и маркеры удаления каждого точного ключа. Похожие ключи
не затрагиваются. Отсутствующий файл или bucket считается уже очищенным;
ошибка доступа, сети или оставшаяся версия не игнорируется.

После очистки MinIO одна транзакция PostgreSQL сохраняет полный снимок в
object_deletion_audit, удаляет объект с зависимостями и переводит операцию
в COMPLETED. Снимок содержит автора, время, все поля объекта, контакты,
задачи, вложения, комментарии, историю и согласования. Снимок защищён от
UPDATE, DELETE и TRUNCATE. Контакты остаются; удаляются только связи с этим
объектом. Оповещения и outbox-события удалённого объекта/его задач очищаются.
Справочники, шаблоны задач и данные других объектов сохраняются.

## Ошибки и восстановление

PostgreSQL и MinIO не имеют общей транзакции. Поэтому это сохраняемая
операция с повторами, а не синхронный DELETE с восстановлением файлов.
202 означает принятие; физическое удаление подтверждается COMPLETED.

При частичной очистке MinIO данные объекта и всех зависимостей остаются в
базе, объект остаётся заблокированным. Уже удалённые версии не возвращаются;
последующая попытка безопасно продолжает очистку. Ошибка записи Audit Log,
каскада или фиксации транзакции сохраняет PENDING; отсутствующие файлы не
мешают повтору. Операция переживает перезапуск процесса. Новых запросов от
администратора для повторов не требуется. Принятая операция продолжает
выполняться при последующей деактивации инициатора; первоначальное
разрешение и имя автора неизменяемы.

Повторы: 2, 4, 8 секунд и далее до часа; лимита попыток нет. Нужен мониторинг
долго ожидающих операций и last_error. Обработчик запускается каждые
5 секунд, максимум 10 операций за проход. Настройки:
`app.objects.deletion.worker-enabled` (true) и
`app.objects.deletion.poll-delay-ms` (5000).
Переменные окружения: OBJECT_DELETION_WORKER_ENABLED и
OBJECT_DELETION_POLL_DELAY_MS. Таймауты SDK: подключение
5 секунд, чтение/запись 30 секунд. Ошибка хранится как STORAGE_UNAVAILABLE
или DATABASE_FAILURE; детали и ключи файлов не передаются клиенту.

## Миграции и совместимость

Добавлены владельцы файлов и комментариев объекта/задач, поскольку API
загрузки и комментариев ещё не реализованы в текущей ветке. Их будущие
операции должны использовать эти таблицы и учитывать блокировку удаления.
Размер файла ограничен 20 МБ, комментарий — 1000 символами; один файл имеет
ровно одного владельца и уникальный bucket/key.

Записи object_creation_requests сохраняются как tombstone: повтор ключа
создания удалённого объекта возвращает 404 и не создаёт объект заново.
object_duplicate_decisions сохраняет идентификатор как аудит решения.
Завершённые операции и снимки сохраняются при rollback. Откат запрещён,
пока есть PENDING; сначала требуется завершить операции. Откат таблиц
владения запрещён при наличии файлов или комментариев; пустые таблицы
удаляются. Откат не восстанавливает физически
удалённые объекты и файлы. Перед merge ветка обновляется от develop после
слияния предыдущих задач модуля Objects.
