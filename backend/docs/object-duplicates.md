# Проверка дублей объекта

T5772. Проверка включена в `POST /api/objects` после валидации, проверки прав и определения адреса/региона, до сохранения. Работает для `MANAGER` и `REGIONAL_MANAGER` по правилам создания T5771.

## Поиск

Объект считается возможным дублем, если выполняется хотя бы одно условие:

- вход находится в заданном радиусе от нового входа;
- нормализованный адрес совпадает;
- триграммная схожесть названия выше заданного порога.

Поиск охватывает все регионы и статусы, включая `REFUSED`. Несколько совпавших признаков одного объекта дают одну строку. Результаты отсортированы по расстоянию, затем UUID; возвращаются 20 ближайших и общее число. Расстояние в метрах вычисляется по формуле haversine, радиус Земли 6371008.8 м, без PostGIS.

Адрес и название приводятся к нижнему регистру; пунктуация заменяется пробелами, повторные пробелы удаляются. Пустой адрес/название не создаёт текстового совпадения. Адрес ищется по равенству, название — средствами [PostgreSQL pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html). Поиск не исправляет сокращения и опечатки в адресе. Координаты ищутся независимо от текстовых признаков.

Настройки в `.env`, передаются приложению через Compose:

```dotenv
OBJECT_DUPLICATE_RADIUS_METRES=50
OBJECT_DUPLICATE_NAME_SIMILARITY=0.6
```

Радиус: 1–10000 м. Порог: строго между 0 и 1. Значение 0.6 выбрано как исходная настройка; клиент не задал числовой порог. Сравнение схожести строго `>`, расстояния — `<=`. Ошибочная настройка останавливает запуск с ошибкой валидации.

## Ответ и решение пользователя

Если дублей нет, возвращается обычный `201`. Если они найдены и `confirmDuplicates` отсутствует, равен `false` или `null`, возвращается `409` со стандартными полями ошибки и дополнительным блоком:

```json
{
  "code": "DUPLICATES_FOUND",
  "duplicates": {
    "total": 1,
    "items": [{
      "id": "00000000-0000-0000-0000-000000000001",
      "name": "Приміщення",
      "address": "Київ, Нова вулиця, 10",
      "status": "REFUSED",
      "statusName": "Відмова",
      "refused": true,
      "distanceMetres": 12.4,
      "restricted": false
    }]
  }
}
```

Предупреждение не создаёт объект, запись истории или резерв ключа. Клиент предлагает действия «Создать всё равно» и «Отменить».

При подтверждении повторите `POST /api/objects` с тем же телом и `Idempotency-Key`, добавив `"confirmDuplicates": true`. Флаг не участвует в fingerprint; остальные поля должны совпадать при повторе уже завершённого запроса. После сохранения ответ `201`. Повтор после успешного создания возвращает тот же объект без новой записи журнала, даже если флаг не передан.

Поиск повторяется при подтверждении, поэтому решение записывается с актуальным числом совпадений. Весь этап поиска/сохранения сериализован транзакционной блокировкой PostgreSQL; параллельный новый запрос увидит объект, сохранённый первым. Геокодирование выполняется до этой блокировки. Блокировка глобальная, поскольку одинаковые адреса и названия могут находиться далеко друг от друга.

При отмене отправьте `POST /api/objects/duplicate-cancellations` с исходным телом и ключом, без `confirmDuplicates: true`. Ответ `204`, повтор идентичен и не создаёт второй журнал. Завершённый отменой ключ нельзя использовать для создания; новая попытка требует нового ключа. Эндпоинт требует действующую сессию, CSRF, валидное тело и права создания.

## Доступ к совпадениям

Менеджер видит полные сведения только своих объектов. Региональный видит полные сведения объектов своего региона. Для всех остальных совпадений возвращаются только `name`, `distanceMetres` и `restricted: true`. UUID, адрес, статус, пометка отказа, координаты, менеджер и регион не раскрываются. Обезличенные результаты имеют отдельный тип ответа, в котором этих полей нет.

```json
{"name": "Інший об’єкт", "distanceMetres": 24.1, "restricted": true}
```

## Журнал, история, миграция

Подтверждение сохраняет `CREATED` в `object_duplicate_decisions`: автор решения, ключ и hash запроса, UUID созданного объекта, общее число дублей и UUID 20 ближайших. В `object_history` созданного объекта добавляется `DUPLICATES_CONFIRMED` с числом совпадений. Обычная запись `CREATED` сохраняется. Все записи и объект коммитятся одной транзакцией; ошибка журнала или истории откатывает создание и ключ.

Отмена сохраняет `CANCELLED` в журнале решений. Объект при отмене не существует, поэтому история объекта и фиктивная карточка не создаются. История найденных чужих объектов также не изменяется.

Новые Liquibase changeset добавляют расширение `pg_trgm`, вычисляемые столбцы нормализованного текста, индексы координат/адреса/названия, функции поиска и журнал. Опубликованные миграции не меняются. Вычисляемые столбцы обновляются PostgreSQL при изменении названия/адреса.

Если `pg_trgm` уже установлен, changeset расширения пропускается и откат его сохраняет. Если установлен этой миграцией, откат удаляет его с `RESTRICT`: при появлении сторонних зависимостей удаление завершится ошибкой, не удаляя их. Права пользователя миграций должны разрешать создание расширения. Откат журнала удаляет его записи; перед откатом на рабочем окружении сохраните журнал по принятой процедуре резервирования.

Контракт: [openapi/objects.yaml](openapi/objects.yaml). Проверки: `mvn -Pintegration verify` на Java 21 с Docker.
