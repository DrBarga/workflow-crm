# Экспорт реестра объектов

T5784 добавляет асинхронный экспорт CSV и XLSX. API использует действующую
сессию, CSRF и текущие права из базы. Подключение интерфейса относится к T5801.

## Запрос и получение файла

`POST /api/objects/export` принимает JSON:

```json
{"format":"XLSX","status":"FOUND","q":"Київ","sort":"name","direction":"asc"}
```

Формат обязателен: CSV или XLSX, без учёта регистра. Поля `status`, `managerId`,
`regionId`, `objectType`, `q`, `createdFrom`, `createdTo`, `sort`, `direction`
проверяются тем же парсером, что [список](object-list.md). `limit`, `cursor`,
неизвестные поля и некорректные значения дают 422. Экспорт включает всю
выборку, а не текущую страницу; сортировка и обработка null совпадают со списком.

Ответ 202 содержит `id`, `state=QUEUED`, `format`, `requestedAt`, `expiresAt`,
`rows=0`, `error=null`. Заголовок Location указывает на
`GET /api/objects/exports/{id}`. Все ответы имеют `Cache-Control: no-store`.

Клиент опрашивает состояние, например раз в две секунды. QUEUED включает ожидание,
обработку и повтор после временной ошибки. READY означает готовность файла;
FAILED — обработка прекращена; EXPIRED — срок хранения закончился.
`GET /api/objects/exports/{id}/download` выдаёт подписанную ссылку и её expiresAt.
Для незавершённой выгрузки возвращается 409, для истёкшей — 410.
Отсутствующая или чужая выгрузка даёт 404. Ошибка MinIO при выдаче ссылки даёт 503.

## Доступ и состав

Провідний экспортирует явно назначенные регионы. Директор з розвитку, CEO и
Адміністратор экспортируют всю сеть. Менеджер и Погодження договорів получают 403.
Текущая роль и набор регионов проверяются при запросе, обработке и получении ссылки.
Если права изменились, требуется новая выгрузка. Существующая подписанная ссылка
действует до конца своего короткого срока жизни. Другой пользователь, включая
администратора, не может получить результат выгрузки инициатора.

Колонки соответствуют полям реестра: id, название, координаты, статус, тип,
адрес, регион, менеджер, автор, версия и время; площади, все структурированные
технические и коммерческие поля, текстовые описания, решение ІК, причина отказа,
предыдущие статусы, даты подписания, приёмки строительства, открытия и акта оплаты
(план и факт), Google Maps. `ObjectExportColumns` задаёт общий состав для обоих
форматов. Приватные поля урезанного объекта заполняются пустыми значениями.
Тип договора и его id не включаются для Адміністратора, как в карточке объекта.
Телефоны и другие контактные данные в этот экспорт не входят.

Читается согласованный снимок БД на начало фоновой обработки. Объекты,
созданные после запроса, и объекты с ожидающим физическим удалением исключаются.
Правки существующих объектов до начала обработки попадут в выгрузку.
Пустая выборка создаёт файл с заголовками.

CSV: UTF-8 с BOM, запятая, CRLF, все ячейки заключены в кавычки;
кавычки и переносы строк экранируются. Текст, начинающийся с формулы, защищается
апострофом, включая формулы после пробельных символов. XLSX хранит пользовательский
текст как строки, не создаёт формул и гиперссылок; точные числа до 15 значащих цифр
пишутся числовыми ячейками, остальные — текстом. Даты записываются в ISO.
После 1048575 строк данных создаётся следующий лист с теми же заголовками.
Для XLSX лимит ячейки 32767 символов; для CSV — 1048576. Значения не обрезаются:
при превышении выгрузка завершается EXPORT_LIMIT. Для длинного текста используйте CSV.

## Очередь и хранение

Очередь `object_exports` сохраняется в PostgreSQL. Каждый экземпляр приложения
имеет один выделенный поток без очереди в памяти. Планировщик только запускает
работу, обработка файла не занимает его поток или HTTP-поток. `FOR UPDATE SKIP LOCKED`
защищает запись от параллельной обработки. Транзакция держит одну связь с БД
на время выгрузки; серверный курсор читает по 32 строки, XLSX удерживает 10 строк.
При остановке процесса транзакция откатывается и работа остаётся в очереди.

MinIO используется через существующие BinaryFileStorage и BinaryStorage.
Приватный бакет, ключ `exports/{actor}/{job}/registry.{format}`, подписанная ссылка.
Результаты не связаны с вложениями объекта и не используют лимит загрузки 20 МБ.
Перед повтором удаляются все версии прежнего артефакта. Успех и запись
EXPORT_COMPLETED фиксируются одной транзакцией. После сбоя записи в БД
файл недоступен через API и удаляется при повторе либо по сроку хранения.
EXPORT_REQUESTED и EXPORT_COMPLETED пишутся в `object_export_audit`; журнал
сохраняется после удаления артефакта. Удаление объектов не удаляет журнал экспорта.

Временные ошибки повторяются до трёх попыток с задержками 10 и 20 секунд.
Ошибки прав и лимитов не повторяются. Коды: PERMISSIONS_CHANGED,
STORAGE_UNAVAILABLE, EXPORT_LIMIT, EXPORT_FAILED. Пользовательский интерфейс
показывает понятное сообщение по коду, не стек ошибки.
Не более двух ожидающих работ на пользователя и ста на экземпляр базы;
превышение возвращает 429. Просроченные артефакты удаляются тем же работником;
ошибка хранилища оставляет работу для следующей попытки очистки.

Настройки: OBJECT_EXPORT_WORKER_ENABLED=true, OBJECT_EXPORT_POLL_DELAY_MS=1000,
OBJECT_EXPORT_BUCKET=workflow-exports, OBJECT_EXPORT_RETENTION=24h (1 минута–7 дней),
OBJECT_EXPORT_LINK_TTL=5m (1 секунда–15 минут), OBJECT_EXPORT_MAX_FILE_BYTES=268435456
(1 МБ–1 ГБ). Лимит ограничивает размер готового файла и текстовый объём XLSX.
Ссылки не живут дольше артефакта. При изменении бакета старые работы очищаются
по сохранённому в записи бакету.

ObjectExportLoadIT проверяет оба формата на 50001 объекте и параллельные HTTP-запросы
списка, не требует ручного запуска работника. Замеры находятся в игнорируемом
target/t5784-load.json. После слияния зависимостей выполняется проверка на стенде.
