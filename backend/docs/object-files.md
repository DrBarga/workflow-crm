# Файлы объекта

T5782, PRD FR-56–59 и NFR-18. Общий сервис хранения описан в
[minio-storage.md](minio-storage.md). API работает с вложениями объекта. Файлы задач
продолжают принадлежать задачам; их загрузка в этот контракт не входит.

| Метод | URL | Ответ |
|---|---|---|
| POST | `/api/objects/{id}/files` | 201, метаданные файла и Location |
| GET | `/api/objects/{id}/files` | 200, `items`, `nextCursor`, `hasMore` |
| GET | `/api/objects/{id}/files/{fileId}` | 200, `url`, `expiresAt` |
| DELETE | `/api/objects/{id}/files/{fileId}` | 204, мягкое удаление |

POST принимает multipart/form-data: ровно один файл в части `file` и один
`categoryId` из активного справочника. Другие части, поля, несколько файлов,
неизвестная или неактивная категория дают 422. Автор и время назначаются
сервером. Передавать storage key, URL, автора, дату или objectId в теле нельзя.

Метаданные: `id`, `category: {id,code,name}`, `author: {id,name}`, `name`,
`contentType`, `sizeBytes`, `createdAt`, `canDelete`. Время передаётся в UTC,
ISO 8601. Секреты, bucket и storage key в ответ не включаются. У прежних файлов
без категории `category=null`; они остаются обычными вложениями.

## Права

Права проверяются в БД на каждом запросе. Для изменения блокируются текущий
пользователь и объект; область доступа и категория проверяются повторно.
CONTRACT_MANAGER работает с файлами всей сети независимо от статуса объекта.

| Роль | Обычные файлы | Договоры | Загрузка | Удаление |
|---|---|---|---|---|
| MANAGER | Свои объекты в назначенных регионах | Там же | Там же | Свои файлы либо файлы своих объектов |
| REGIONAL_MANAGER | Явно назначенные регионы | Там же | Там же | Файлы объектов явно назначенных регионов |
| DEVELOPMENT_DIRECTOR | Вся сеть | Вся сеть | Вся сеть | 403 |
| CONTRACT_MANAGER | Вся сеть | Вся сеть | Вся сеть | Только свои файлы |
| CEO | Вся сеть | Вся сеть | 403 | 403 |
| SUPERADMIN | Вся сеть | 403 | 403 | Все обычные файлы; договоры — 403 |

Ограничение определяется `file_categories.is_restricted`. Файлы ограниченных
категорий исключаются из SQL-выборки до пагинации. Администратор не получает
названия или идентификаторы договоров через список, а прямой запрос ссылки
возвращает 403. По уточнению T5782 администратор не может удалить договор,
даже зная его ID; проверка выполняется до изменения файла и истории. Право
удаления и поле canDelete используют одну политику. Прежний менеджер может удалить своё
вложение после перепривязки, но не получает доступ к чужому объекту или его
другим файлам. Проверяются все назначенные регионы пользователя; для провідного
учитываются их дочерние регионы. Деактивация либо смена роли отменяет прежние полномочия.

Cookie-сессия обязательна. POST и DELETE требуют текущий CSRF cookie и
`X-XSRF-TOKEN`. Метаданные и ссылки имеют `Cache-Control: no-store`.
Файл другого объекта, отсутствующий либо удалённый файл возвращает 404.
Во время физического удаления объекта T6797 все методы возвращают 409.

## Ограничения и MinIO

По умолчанию допустимы jpg, png, pdf, docx, xlsx, dwg; предел —
20 МиБ (20971520 байт). HEIC из PRD можно явно включить в FILE_ALLOWED_EXTENSIONS.
Размер и разрешённое подмножество форматов задаются
в настройках. Более высокий предел требует отдельной миграции ограничения БД.
Пустой файл, неподходящий формат, недопустимое имя или несоответствующая
сигнатура дают 422 с полем `file`. MIME определяется сервером по формату;
переданный Content-Type не используется как доказательство формата.
Для docx/xlsx проверяется ZIP-контейнер и обязательные элементы документа;
объём распаковки ограничен. Проверка формата не заменяет антивирус.

HTTP multipart ограничен 20 МиБ для части и 21 МиБ для всего запроса. Если
запрос отвергнут контейнером до чтения файла, ответ — 413. Это отличается
от 422 при нарушении прикладных настроек. Файл читается с верхней границей,
поток закрывается. Ключ MinIO генерируется сервером независимо от имени.
Параллельные загрузки не перезаписывают друг друга.

Bucket должен быть закрыт для анонимного доступа. Новый bucket создаётся
без публичной policy. Файл открывается только после проверки
прав через подписанный GET URL. Срок по умолчанию пять минут, допустимы
1 секунда–15 минут. Подпись задаёт `attachment` и `application/octet-stream`.
Ссылки нельзя публиковать или сохранять как постоянные ссылки комментариев;
в комментарии используйте путь API с fileId, затем запросите актуальный URL.
Параметры ссылки и их значения нельзя менять после подписания.

| Переменная | Значение по умолчанию |
|---|---|
| FILE_BUCKET | workflow-files |
| FILE_MAX_SIZE_BYTES | 20971520 |
| FILE_ALLOWED_EXTENSIONS | jpg,png,pdf,docx,xlsx,dwg |
| FILE_LINK_TTL | 5m |
| MINIO_PUBLIC_ENDPOINT | MINIO_ENDPOINT, если отдельный адрес не задан |
| MINIO_REGION | us-east-1 |
| FILE_UPLOAD_CLEANUP_ENABLED | true |

MINIO_ENDPOINT используется приложением для записи и удаления. Для стенда
MINIO_PUBLIC_ENDPOINT должен указывать на доступный браузеру HTTPS S3 endpoint
в инфраструктуре Workflow. Прокси должен сохранять подписанные Host, путь и query;
переадресовывать подписанную ссылку на другой host нельзя. Значение региона
должно совпадать с MinIO. Настройка публичного endpoint не открывает bucket:
анонимный доступ и публичная bucket policy не нужны.

## Удаление, история и восстановление после ошибок

Удаление мягкое, согласно FR-59. Строка получает deleted_at; список и API
перестают выдавать файл, повторный DELETE возвращает 404. Байты сохраняются
до физического удаления объекта. Комментарии с его ссылкой остаются с прежним
текстом; переход по API этой ссылки даёт 404. Ранее выданный presigned URL
действует до своего срока истечения: мягкое удаление не отзывает уже выданные
подписи MinIO. Клиент должен запрашивать новую ссылку при открытии файла.

FILE_UPLOADED и FILE_DELETED записывают метаданные, автора и время в историю
в одной транзакции с файлами. Ошибка истории откатывает запись или deleted_at.
Версия объекта не меняется; запросы согласования остаются актуальными.

Перед записью в MinIO создаётся отдельное долговечное резервирование ключа.
Транзакция публикации блокирует резервирование, сохраняет файл и историю,
затем удаляет резервирование. Если приложение завершится или БД откатит
операцию после записи байтов, резервирование остаётся. Очистка после десяти
минут удаляет все версии этого ключа, имеет блокировку SKIP LOCKED и повтор
через минуту при ошибке. Незавершённая загрузка никогда не попадает в список.
Ошибка MinIO возвращает 503. Успешные загрузки не попадают в очистку.
Для multipart-загрузок, прерванных завершением процесса до сборки объекта
MinIO, инфраструктура должна настроить lifecycle AbortIncompleteMultipartUpload:
очистка резервирований удаляет готовые объекты и их версии, а не отдельные
незавершённые части S3.

T6797 удаляет все версии обычных и мягко удалённых файлов, после чего удаляет
строки каскадно. Метаданные и история остаются в снимке Audit Log объекта.

## Пагинация и миграция

Порядок списка — по sequence от старых к новым. По умолчанию limit=50,
диапазон 1–100. Курсор привязан к объекту и верхней границе первой страницы;
новые загрузки видны при новом чтении. Удаление последней строки страницы
не ломает продолжение. Запрос читает не более limit+1 строк, без OFFSET/COUNT.
Некорректный или чужой курсор и диапазон limit дают 422.

Changeset 20261009-object-files добавляет последовательность, индексы и
резервирования. Старые метаданные, авторы, категории и deleted_at сохраняются.
Перед обновлением нужно завершить PENDING удаления объектов. Rollback
сохраняет файлы, но требует сначала очистить незавершённые резервирования.
Опубликованные предыдущие changeset не меняются.
