# История объекта

`GET /api/objects/{id}/history` возвращает `items`, `nextCursor`, `hasMore`.
Каждая запись содержит `id`, `sequence`, `occurredAt`, `author`, `field`,
`previousValue`, `newValue`, `objectVersion`. Время — ISO 8601 UTC; интерфейс
отображает его в Europe/Kyiv. Значения существующих записей сохраняются без
преобразования: обычная строка или сериализованный JSON.

Автор пользователя: UUID, `USER`, текущее имя из реестра пользователей.
Системный автор: `id=null`, `SYSTEM`, `Система`. Отсутствие пользователя
не исключает системные записи из выдачи.

## Доступ

Проверка использует общий `ObjectCardAccess.full`: менеджер — собственный
объект в своём регионе; провідний — явно назначенные регионы; директор, CEO
и Адміністратор — вся сеть. Технический просмотр Погодження договорів
и минимальный просмотр чужого объекта не дают доступа к истории: `403`.
Права, текущий владелец и активность пользователя проверяются на каждой
странице. Отсутствующий объект — `404`; ответ имеет `Cache-Control: no-store`.
Чтение права и истории выполняется в одной транзакции `REPEATABLE_READ`.

## Пагинация

`limit` по умолчанию 50, допустимы 1–100. `cursor` берётся из `nextCursor`
предыдущей страницы того же объекта. Курсор не даёт дополнительных прав.
Некорректный курсор или диапазон limit — `422`, некорректный тип — `400`.

История идёт в порядке записи по монотонному `sequence`. Для прежних записей
миграция восстанавливает порядок по `created_at,id`. Запрос использует индекс
`(object_id,sequence)` и читает не более `limit+1` строк. Курсорная пагинация
не использует OFFSET и не требует подсчёта всей истории. Новые события видны
на следующих страницах; завершённую ленту для новых событий перечитывают.

## Записываемые события

Существующие операции сохраняют создание (`CREATED`), подтверждение дубля
(`DUPLICATES_CONFIRMED`), смену статуса, решение ІК, очистку полей при возврате,
редактирование, координаты, Google Maps, перепривязку менеджера и отсутствие
активного шаблона (`TASK_TEMPLATE_MISSING`). Их формат и правила не меняются.

Триггеры таблиц согласований записывают создание запроса и изменение его
состояния: `STATUS_APPROVAL_*`, `ENTRY_POINT_APPROVAL_*`. Запись создаётся
в той же транзакции, включая `APPROVED`, `REJECTED`, `CANCELLED`, `STALE`.
Изменение без смены состояния не создаёт повтор. `STALE` без решающего
пользователя записывается системой. Старые запросы восстанавливаются
миграцией; для прежнего решения сохраняется известная версия из запроса.

Для связанных модулей есть `objects::api/ObjectHistoryEvents`:

```java
history.record(objectId, actorId, objectVersion,
        ObjectHistoryEvents.Type.FILE_UPLOADED, null, fileMetadata);
```

Вызов требует транзакцию операции; блокирует строку объекта и проверяет
версию. Допустимы `FILE_UPLOADED`, `FILE_DELETED`, `TASK_DEADLINES_SHIFTED`,
`TASK_STATUS_CHANGED`, `COMMENT_CREATED`, `COMMENT_EDITED`, `COMMENT_DELETED`. Комментарии T5780
записывают события вместе с изменением комментария; значения содержат
прежнюю и новую публичную запись комментария.
`actorId=null` означает систему. В значения передают идентификатор/имя/категорию
файла либо изменения сроков с причиной; секреты и временные ссылки не передают.
При откате операции история также откатывается. Повтор доставки обязан
отсечь вызывающий модуль своим ключом идемпотентности до вызова записи.

Загрузка и удаление файлов T5782 записываются через `ObjectFileContext`.
Синхронное событие `tasks::api/TaskStatusChanged` связывает модули без
обратной зависимости Tasks от Objects. Отмена задач при переходах `CANCEL` и `CANCEL_ALL` записывает
`TASK_STATUS_CHANGED` для каждой изменённой задачи. Оба значения — JSON
с `taskId`, `name`, `status`, `version`. Автор — инициатор перехода объекта;
завершённые задачи, ранее отменённые и задачи чужих объектов не затрагиваются.
Повтор с устаревшей версией не добавляет записей.

Связанные операции могут вызвать перегрузку `record` без `objectVersion`:
она блокирует объект и использует его текущую сохранённую версию, не меняя её.
При отмене задач это версия до сохранения перехода объекта; последующая запись
смены статуса объекта содержит уже новую версию. История задач, история объекта,
отмена, outbox и уведомления фиксируются одной транзакцией. При работе с несколькими
объектами вызывающий сценарий должен блокировать объекты в стабильном порядке до задач.

Массовый сдвиг сроков относится к Epic Tasks. Для него подготовлен и проверен
`TASK_DEADLINES_SHIFTED`; подключение выполняется вместе с реализацией сдвига.
Прежние статусы задач задним числом не восстанавливаются: новые события
записываются после обновления приложения. Миграция для этого изменения не нужна.

## Неизменяемость и удаление

У API истории нет методов изменения/удаления. Hibernate entity — `@Immutable`.
PostgreSQL отклоняет UPDATE, DELETE и TRUNCATE истории. Единственное
исключение DELETE — каскад после удаления родительского объекта с созданным
снимком в `object_deletion_audit`.

Миграция готовит физическое удаление T6797. Перед удалением в транзакции
сервер устанавливает подтверждённого пользователя:

```sql
SELECT set_config('workflow.object_deletion_actor', :authenticatedActorId, true);
```

Триггер допускает только активного SUPERADMIN. Снимок строки объекта и
связанных контактов сохраняется до удаления; таблица аудита не имеет FK
на объект/пользователя и защищена от UPDATE, DELETE и TRUNCATE. Другие
зависимости объекта и подтверждение удаления обрабатывает T6797. Публичного
DELETE объекта эта задача не добавляет. Контекст транзакционный и не должен
приниматься из тела запроса.

## Миграция и откат

`20261008-object-history` подключается после модулей согласования и аудита.
Повтор применения не добавляет событий; rollback сохраняет записи истории
и снимки удаления. `object_deletion_audit` и её защита остаются после rollback:
откат схемы не уничтожает доказательства уже выполненного удаления. При
повторном применении backfill не дублирует восстановленные запросы.

Роль приложения в production не должна владеть таблицами или иметь право
ALTER TABLE/TRIGGER. DDL выполняется учётной записью миграций. Как и любые
триггеры, эта защита не ограничивает администратора самой PostgreSQL.
