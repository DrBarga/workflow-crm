# Импорт объектов

T5785, FR-60. Все операции доступны только активному `SUPERADMIN`.
Права проверяются при загрузке, чтении состояния/отчёта и обработке задания.
Другие роли получают `403`.

## Шаблон и загрузка

`GET /api/objects/import/template?format=xlsx` скачивает шаблон v2 (`objects-import-v2.xlsx` или `.csv`). Доступны
`xlsx` (по умолчанию) и `csv`. XLSX содержит один лист `Objects`, CSV — UTF-8,
разделитель запятая, допускается BOM. Заголовки и порядок столбцов фиксированы;
используйте скачанный шаблон. Все ответы содержат `Cache-Control: no-store`.

В шаблоне v2 нет колонки `openingPlannedDate`: система рассчитывает её из
плановой даты акта БМР и срока строительства. Файл с прежней колонкой или
другим составом заголовков отклоняется целиком до постановки в очередь.
Данные такого файла нужно перенести в актуальный шаблон.

`POST /api/objects/import` принимает multipart-поле `file`, cookie сессии и
`X-XSRF-TOKEN`. Ограничения: 20 МБ, 10 000 строк данных, 64 МБ распакованного XLSX.
Формулы не вычисляются: строки с такими ячейками отклоняются. Неправильный
шаблон, повреждённый файл, лишние столбцы, неверная кодировка или превышение
лимита отклоняют весь файл с `422` до создания задания. До десяти заданий
могут ожидать обработки; переполненная очередь возвращает `429`.

Ответ `202` содержит `id`, `author`, `state`, `total`, `created`, `rejected`,
`duplicates`, `requestedAt`, `completedAt`, `error`. `Location` указывает
`/api/objects/imports/{id}`. Семантическая проверка и создание объектов идут
в отдельном воркере, а не в потоке HTTP-запроса.

Повторная загрузка идентичных байтов возвращает прежнее задание, независимо
от имени файла и администратора. SHA-256 уникален в базе; параллельные загрузки
не создают два задания. Даже после удаления импортированного объекта такой
файл не создаст его повторно. Изменённый файл считается новым импортом.

## Поля

Названия столбцов соответствуют API ручного создания, включая вложенные пути:

- Основные: `name`, `objectType`, `address`, `regionId`, `managerId`,
  `entrance.longitude`, `entrance.latitude`, `objectArea`, `landArea`.
- Контакт: `contact.name`, `contact.role`, `contact.phone`, `contact.email`.
- Технический блок: `technicalSpecifications.buildingArea`, `firstFloorArea`,
  `secondFloorArea`, `basementArea`, `salesHallArea`, `floorSlabHeight`,
  `connectedPower`, `waterSupplyFlow`, `powerConnectionCategory`, `sewageType`
  (каждый столбец с префиксом `technicalSpecifications.`).
- Коммерческий блок: `commercialTerms.leaseTerms`, `fixedRentAmount`,
  `rentIndexationPercent`, `turnoverPaymentPercent`, `counterpartyTaxStatus`,
  `constructionTermDays`, `contractDurationYears`
  (каждый столбец с префиксом `commercialTerms.`).
- Плановые даты: `constructionAcceptancePlannedDate`,
  `paymentActPlannedDate`. CSV использует `yyyy-MM-dd`; XLSX принимает также
  ячейки Excel с форматом даты.

`openingPlannedDate` вычисляется как `constructionAcceptancePlannedDate` плюс
`commercialTerms.constructionTermDays` в календарных днях, включая выходные.
При нулевом сроке дата совпадает с датой акта БМР. Если хотя бы одно исходное
поле пустое, плановая дата открытия остаётся пустой. Поддерживаются также
`preliminaryContractSignedDate`, `commissioningDate` и `shortComment` до 200 символов.

Уже принятые задания со строками прежнего формата остаются в очереди.
Если сохранённая строка содержит `openingPlannedDate`, значение проверяется
на совпадение с расчётом. Несовпадение отклоняет строку с причиной в отчёте.

Обязательны обе координаты и хотя бы одна положительная площадь.
`managerId` должен указывать активного менеджера того же региона. Регион и
адрес можно оставить пустыми: они определяются обратным геокодированием.
Пустое имя подставляется из адреса по координатам, даже если в строке указан
ручной адрес. Ручной адрес при этом сохраняется. Ограничения длины, типов,
точности чисел, справочников и контактов совпадают с
[ручным созданием](object-creation.md).

Все объекты создаются в `FOUND` («Знайдено»), автором указывается загрузивший
администратор. Импорт не восстанавливает исторические статусы, фактические
даты, решения ІК, тип договора и наборы задач. Фактические даты отсутствуют
в шаблоне: они вносятся через утверждённый workflow.

## Состояние и отчёт

`GET /api/objects/imports/{id}` возвращает состояние:

- `QUEUED`: задание ожидает обработки, обрабатывается либо ожидает повторной
  попытки. До коммита обработка не публикует промежуточные изменения.
- `COMPLETED`: валидные строки созданы, остальные отклонены с причинами.
- `FAILED`: обработка отменена; объекты этого задания не созданы.

`GET /api/objects/imports/{id}/report?offset=0&limit=100` возвращает
`content`, `offset`, `limit`, `total`. `offset >= 0`, `limit` от 1 до 200.
Неизвестный `id` возвращает `404`. Отчёт доступен всем активным администраторам.
Каждая строка содержит `row` (номер записи/строки листа, заголовок — 1),
`state`, `objectId`, `possibleDuplicate`, `note`, `errors`.
Ошибка содержит `field` и `message`; исходные контактные данные в отчёт
не включаются. Строки без данных тоже проходят проверку и получают причины.

Состояния строки: `PENDING`, `CREATED`, `REJECTED`, `NOT_APPLIED`.
Проверка дублей использует тот же поиск, настройки расстояния и схожести,
что ручное создание. Учитываются «Відмова» и предыдущие строки файла.
Дубль создаётся; `possibleDuplicate=true`, `note="можливий дубль"`.
Создание и подтверждение дубля записываются в историю объекта.

## Ошибки и прерывание

Воркер сначала проверяет все строки, затем применяет валидные. Создание
объектов, контактов, история, итоговый отчёт и запись завершения в журнал
коммитятся одной транзакцией. Любая инфраструктурная ошибка откатывает
её целиком. При остановке процесса блокировка PostgreSQL освобождается,
задание с исходными строками остаётся в очереди; другой воркер может его
подхватить. `FOR UPDATE SKIP LOCKED` исключает двойную обработку.

Ошибки обработки автоматически повторяются до трёх попыток с паузой
пять секунд. После третьей ошибки все строки получают `NOT_APPLIED` и
причину отката. Потеря прав администратора завершает задание сразу.
Исходные строки удаляются при завершении; сохраняются итоги и причины.
Ошибка повторного импорта того же файла возвращает прежний отчёт.

Параметры воркера: `app.objects.import.worker-enabled=true`,
`app.objects.import.poll-delay-ms=1000`. Это отдельный поток с ограниченной
очередью; пул HTTP и воркер экспорта не используются. Миграция
`20261010_object_imports.yaml` создаёт задания, строки и журнал и имеет откат.
Интерфейс импорта подключается в T5802.
