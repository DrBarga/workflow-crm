# Список объектов

T5773. `GET /api/objects` возвращает страницу реестра. Доступ и состав каждого объекта проверяются на сервере по текущему пользователю из базы, а не по роли из JWT. Запрос ничего не изменяет; ответ имеет `Cache-Control: no-store`.

## Параметры

| Параметр | Значение |
| --- | --- |
| `status` | Код статуса из справочника |
| `managerId` | UUID ответственного менеджера |
| `regionId` | UUID региона |
| `objectType` | Код типа объекта |
| `createdFrom`, `createdTo` | Даты `YYYY-MM-DD`, включительно, по дате создания в UTC |
| `q` | Подстрока названия или разрешённого адреса, до 200 символов |
| `sort` | `createdAt`, `name`, `status`, `investmentCommitteeDate`, `contractSignedDate` |
| `direction` | `asc` или `desc`; по умолчанию `desc` |
| `limit` | 1–100, по умолчанию 50 |
| `cursor` | Курсор следующей страницы из предыдущего ответа |

Все фильтры объединяются через AND, поиск внутри фильтра — название OR адрес. Коды справочников и направление нечувствительны к регистру. Поиск без учёта регистра, `%`, `_` и обратная косая черта считаются обычными символами. Адрес участвует в поиске только для объектов с полным доступом. Неизвестный код справочника или UUID даёт пустой список; неверный формат, неизвестный/повторный параметр или обратный диапазон дат — 422 с названием поля.

Сортировка статусов идёт по `object_statuses.sort_order`, названий — по `lower(name)` с collation базы. `investmentCommitteeDate` — фактическая дата ІК. `contractSignedDate` — дата подписания основного договора; дата предварительного договора `preliminaryContractSignedDate` не участвует в сортировке и не заменяет отсутствующую дату основного. Во всех сортировках NULL идёт в конце при обоих направлениях; UUID служит вторым ключом. По умолчанию новые объекты идут первыми.

## Видимость

| Роль | Строки и поля |
| --- | --- |
| `MANAGER` | Назначенные регионы, основной и дополнительные. Свои объекты — полные; чужие — ровно `name` и `entrance`, без UUID, адреса, статуса и других полей |
| `REGIONAL_MANAGER` | Вся сеть. В явно назначенных регионах — полные объекты; в остальных — ровно `name` и `entrance` |
| `DEVELOPMENT_DIRECTOR`, `CEO`, `SUPERADMIN` | Полные объекты всей сети |
| `CONTRACT_MANAGER` | Вся сеть, включая ранние статусы: `name`, `entrance`, `technicalSpecifications`, `technicalDescription` |

Фильтр пересекается с областью видимости. Чужой регион для менеджера возвращает 200 с пустым `content`, а не 403. Для провідного такой фильтр возвращает только названия и координаты. Все прежние фильтры, их сочетания и сортировка сохраняются; адрес участвует в поиске провідного только в регионах с полным доступом. Неизвестный регион возвращает пустую страницу. Неактивный или отсутствующий пользователь получает 403. Без назначенных регионов менеджер получает пустой список, провідний — только названия и координаты по сети.

Назначения читаются из Users при каждом запросе. Все регионы берутся только из user_regions; наследования по иерархии нет. Смена или отзыв назначения инвалидирует выданный курсор. Ограниченная строка не содержит UUID, статуса, адреса, технических, коммерческих и контактных полей; полные данные таких строк не загружаются. Экспорт T5784 сохраняет ограничение провідного своими регионами и не выгружает чужие пины списка. Права карточки и операций изменения этой доработкой не расширяются.

Для договорной роли в этом списке действует конкретный критерий T5773 «все объекты сети в ограниченном составе». Более ранний BRL-04 о карточке/договорах не расширяет доступ к коммерческим данным, контактам или файлам и не ограничивает этот реестр поздними статусами. Другие API доступа не изменены.

Полная строка содержит поля создания на верхнем уровне и `workflow`: состояние до паузы/отказа, решение и дату ІК, условия/комментарий, тег отказа, тип договора, фактические и плановые даты, время изменения. `shortComment` — короткий комментарий до 200 символов на верхнем уровне полной строки. При отсутствии значения возвращается null. Менеджер видит комментарий только у своих объектов, провідний — только в назначенных регионах, директор, CEO и Адміністратор — по сети. У ограниченных пинов и договорной роли поле отсутствует, включая значение null. Комментарий не расширяет поиск по названию и адресу. Техническое и коммерческое текстовые описания представлены отдельно от структурированных блоков. Номер телефона в контактном блоке маскируется как `***`; его открытие с аудитом относится к Epic Contacts. Список не открывает защищённый номер обходным путём.

## Пагинация

```json
{
  "content": [{"name": "Приміщення", "entrance": {"longitude": 30.5, "latitude": 50.4}}],
  "nextCursor": "<непрозрачный курсор>",
  "hasMore": true
}
```

При `hasMore=true` повторите тот же запрос с теми же параметрами и полученным `cursor`. При изменении пользователя, области видимости, фильтров, сортировки, направления или размера страницы начните заново. Курсор живёт 15 минут и шифруется AES-GCM с проверкой целостности; UUID и скрытый ключ сортировки нельзя прочитать из него. Другой пользователь, подмена, истечение срока или изменение параметров дают 422 по полю `cursor`. `OBJECT_LIST_CURSOR_SECRET` позволяет задать отдельный секрет минимум из 32 символов; по умолчанию применяется отдельный ключ, выведенный из JWT-секрета. Ротация секрета требует начать список заново.

Запрос использует keyset по ключу сортировки и UUID, без OFFSET и общего COUNT. Читаются `limit+1` строк; подробности загружаются одним пакетным запросом только для строк с полным доступом. Одна страница читается в согласованном снимке REPEATABLE READ. После обновления правил видимости T5773 курсоры прежней версии отклоняются с 422; клиент начинает список заново. Курсор фиксирует верхнюю границу даты создания: новые объекты не сдвигают страницы. Между отдельными HTTP-запросами изменения сортируемых полей могут переместить объект — это живой реестр, не исторический снимок. Удаление граничной строки не ломает продолжение.

## Миграция и проверка

`20261006_object_list` добавляет десять индексов: ключи пагинации, сочетания с регионом/менеджером/статусом/типом и GIN для поиска. Откат удаляет только новые индексы, данные объектов и прежние индексы сохраняются. Опубликованные миграции не переписаны.

`ObjectListVisibilityIT`, `ObjectListFiltersIT`, `ObjectListSortingIT`, `ObjectListCursorIT`, `ObjectListCommentIT`, `ObjectListMigrationIT` проверяют контракт и границы доступа. Сортировка проверяется с несовпадающими датами основного и предварительного договоров; комментарий — для всех ролей и смешанных страниц с полными строками и ограниченными пинами. `ObjectListPerformanceIT` создаёт 50 000 объектов с короткими комментариями до 200 символов в PostgreSQL 17 и измеряет реальный HTTP-ответ Tomcat: 18 сценариев, 3 прогрева и 20 измерений на сценарий, p95 каждого менее 2 секунд. Включены все сортировки в обе стороны, роли, совмещённые фильтры, чужой регион, смешанная видимость провідного, его поиск по адресу и страница после 10 000 строк. Результат записывается в `target/t5773-performance.json`. Это последовательный локальный замер, не обещание производительности промышленного окружения.

Команда: `./mvnw -B -ntp verify -Pintegration -Dit.test=ObjectList*IT -Dmaven.antrun.skip=true`, Java 21, Docker для Testcontainers. HTTP-контракт: [openapi/objects.yaml](openapi/objects.yaml).
