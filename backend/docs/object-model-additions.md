# Джерело об'єкта і скасування всіх задач

Доопрацювання T5770 за двома додатковими критеріями від 13.10.2026.

## Джерело

`object_data_sources` — довідник з UUID, унікальним кодом, назвою, активністю, часом створення та зміни й версією запису. Liquibase створює п'ять значень:

| Код | Назва |
|---|---|
| BROKER | Брокер |
| OWN_SEARCH | Власний пошук |
| ADVERTISEMENT | Оголошення |
| DIRECT_OWNER | Власник напряму |
| OTHER | Інше |

`objects.data_source_id` — необов'язковий зовнішній ключ з індексом. Старі об'єкти отримують null: джерело не визначається за припущенням. Використане значення не можна фізично видалити завдяки ON DELETE RESTRICT; для приховування доступне `is_active`.

JPA-модель підтримує вибір та очищення джерела. Ця задача додає модель зберігання; поле у HTTP-сценаріях створення, редагування й імпорту підключається у відповідних задачах.

## CANCEL_ALL

`unfinished_task_action` допускає BLOCK, CANCEL, CANCEL_ALL і NONE; довжина збільшена до 16 символів. У БД та API використовуються великі літери, як у попередніх значень.

CANCEL_ALL скасовує всі незавершені задачі об'єкта незалежно від початкового статусу. DONE, CANCELLED та задачі інших об'єктів залишаються без змін. Скасування використовує наявну транзакцію, контроль версії, історію задачі, події та сповіщення. Набори без незавершених задач отримують CANCELLED за наявною логікою Tasks.

Для рішення ІК CANCEL зберігає вибірку поточного етапу, CANCEL_ALL охоплює всі етапи. Ручні переходи зберігають раніше погоджену вибірку всіх задач об'єкта. Додавання нового значення не змінює налаштування існуючих переходів, зокрема NONE для рішень ІК.

## Міграція та перевірка

Нові changeset додані після наявних міграцій у master. Повторний update зберігає UUID і кількість рядків довідника. Rollback прибирає новий довідник, посилання й індекс та відновлює початкову довжину і CHECK дії переходу. Налаштований після міграції CANCEL_ALL при відкаті перетворюється на CANCEL: старий формат не може зберігати нове значення. Виконані скасування задач не відновлюються відкатом схеми.

Інтеграційні перевірки охоплюють збереження та очищення джерела, FK та унікальність коду, точні назви сіду, повторне застосування, відкат схеми й збереження старих даних, різницю CANCEL/CANCEL_ALL та незмінність завершених і чужих задач.
