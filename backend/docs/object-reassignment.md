# Перепривязка объекта — T5779

`POST /api/objects/{id}/reassign` меняет ответственного менеджера. Тело содержит только `managerId` и `version` из последней карточки:

```json
{
  "managerId": "00000000-0000-0000-0000-000000000001",
  "version": 3
}
```

Провідний (`REGIONAL_MANAGER`) работает с объектами явно назначенных регионов, директор з розвитку (`DEVELOPMENT_DIRECTOR`) — с любыми объектами сети. Роль, активность и область читаются из базы. Менеджер, CEO, Погодження договорів и Адміністратор не выполняют эту операцию: 403. У администратора сохраняются отдельные права редактирования карточки; они не расширяют право перепривязки из FR-09.

Новый ответственный должен существовать, иметь роль `MANAGER`, быть активным и принадлежать ровно региону объекта. Менеджер другого региона, без региона, с другой ролью или деактивированный получает 422 с `violations.field=managerId`. Для директора исключения из регионального правила нет. Прежний менеджер может быть деактивирован: это не мешает передать его объект.

API возвращает `saved`, `id`, `previousManagerId`, `managerId`, новую `version` и список `transferredTasks`. При выборе текущего менеджера с актуальной версией возвращаются `saved=false` и пустой список; история, версия и уведомления не меняются. Любой запрос с устаревшей версией получает 409, `code=CONCURRENT_UPDATE` и `currentVersion`. Пользователь перечитывает карточку перед повторением. Успешные ответы и конфликты содержат `Cache-Control: no-store`.

## Перенос задач

Переносятся задачи именно этого объекта, где исполнитель — прежний ответственный, а статус не `DONE` и не `CANCELLED`. Это включает `NEW`, `IN_PROGRESS`, `PAUSED` и `WAITING_APPROVAL`. Статус, срок, автор, шаблон, источник и дата создания задачи сохраняются. Версия перенесённой задачи увеличивается один раз. Задачи других исполнителей и других объектов не затрагиваются.

У перенесённой задачи сохраняется `transferred_from_predecessor=true`; ответ содержит `transferredFromPredecessor=true` и метку «задача перейшла від попередника». В `task_assignment_history` записываются прежний и новый исполнитель, инициатор, версия задачи и время. При повторной перепривязке сохраняются все записи передачи. Шаблоны задач не редактируются этой операцией.

## История, уведомления и целостность

История объекта записывает изменение `managerId`, старое/новое значение, автора и версию. Журнал содержит `MANAGER_REASSIGNED` с перечнем перенесённых задач. Outbox получает `OBJECT_MANAGER_REASSIGNED` и события `TASK_REASSIGNED`. Прежнему и новому менеджерам ставится по одному уведомлению `OBJECT_MANAGER_REASSIGNED` в существующую очередь Epic 7. Доставка по каналам остаётся ответственностью воркеров уведомлений.

Регион, автор, статус, координаты, контакт и остальные поля объекта сохраняются. После передачи новый менеджер получает полный доступ к карточке, прежний — ограниченный состав по обычным правилам видимости. Ожидающие запросы изменения статуса и точки входа становятся `STALE`: подтверждение, привязанное к прежнему владельцу и версии, не применяется.

Объект блокируется раньше пользователей и задач. Пользователи блокируются в одинаковом порядке; их активность, роль и регион проверяются под блокировкой. Одновременная деактивация нового менеджера не позволяет назначить его по прежним данным. Задачи блокируются по ID; изменения проверяют их версию. Проверка клиентской версии согласует перепривязку с PATCH и существующими обработчиками статусов. Один запрос сохраняет одну новую версию объекта.

Смена менеджера, перенос задач, метка, обе истории, журнал, outbox, уведомления и инвалидирование запросов выполняются одной транзакцией. Ошибка любого этапа откатывает весь результат.

## Миграция и ошибки

Миграция `20261007_task_reassignment` добавляет метку задач, историю исполнителей и частичный индекс для незавершённых задач объекта. Существующие задачи получают `false`, остальные их поля и объекты сохраняются. Откат удаляет только добавленные индекс, таблицу и колонку; сведения о передачах из новой таблицы при откате будут удалены.

Некорректный JSON или UUID объекта — 400; отсутствие сессии — 401; чужая область или неверный CSRF — 403; отсутствующий/удалённый объект — 404; конфликт версии — 409; отсутствующий, лишний или неверный параметр — 422. Строки, дроби и отрицательные значения вместо целой версии не принимаются.

Контракт: [OpenAPI объектов](openapi/objects.yaml). Фронтенд подключения перепривязки относится к T5800; эта задача реализует серверный API и хранение данных.
