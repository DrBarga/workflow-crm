# Политика переходов объекта

Источник: актуальные детали T6712, 17 критериев и 32 правки от 12.10.2026. Сверено с чатом Влада и карточкой KeySpace 15.10.2026.

## Модель

`objects.status_before_refusal_id` — nullable FK на `object_statuses`, с индексом и ON DELETE RESTRICT. Новая база и обновление существующей базы используют одинаковую схему. Старым объектам оставлено null: без достоверной истории нельзя выдумать этап отказа. Неизвестный этап не даёт менеджеру права восстановления.

Сценарий отказа сохраняет предыдущий этап; при отказе из паузы — этап до паузы. Это позволяет сохранить происхождение отказа даже после последующей постановки отказанного объекта на паузу. Прямое изменение статуса и заполнение этого поля относятся к T6712.

У причины отказа добавлено `is_system_only`: true только у `IC_NOT_APPROVED` («Не погоджено на ІК»). Ручной выбор этой причины недоступен; автоматическое решение ІК использует её через fixed_refusal_reason_id.

У перехода добавлены:

- `unfinished_task_action`: BLOCK, CANCEL, CANCEL_ALL или NONE, ограничено CHECK, обязательное значение по умолчанию NONE.
- `is_unavailable_after_task_creation`: запрет, если по объекту создавался набор или есть исторические задачи, включая завершённые или отменённые. Включён у менеджерских IN_PROGRESS / PAUSED → FOUND; у руководства отдельное правило без запрета.

С 05.10.2026 статус считается триггером при наличии привязанного активного шаблона задач. Фиксированный список и колонка `is_task_generation_trigger` удалены. Конкретный сценарий выбирает шаблон по статусу и типу договора. Состав шаблонов согласовывается с клиентом. Подробнее: [object-fields.md](object-fields.md).

## Таблица T6712

REGIONAL_MANAGER — «Провідний», DEVELOPMENT_DIRECTOR — директор, CONTRACT_MANAGER — «Погодження договорів». В каталоге 56 правил, 55 активных. REQUEST_PAUSED_TO_IC оставлен неактивным для совместимости с прежней миграцией.

| № | Направление и права | Условия | Задачи |
|---|---|---|---|
| 1 | FOUND → IN_PROGRESS: менеджер, провідний, директор | — | NONE |
| 2 | IN_PROGRESS / PAUSED → FOUND: те же роли | Менеджеру недоступен после создания набора задач | CANCEL_ALL |
| 3 | Отказ до ІК: менеджер, провідний, директор | Причина | CANCEL_ALL |
| 4 | FOUND / IN_PROGRESS → IC_PREPARATION: провідний, директор | — | NONE |
| 5 | Те же направления по запросу менеджера | Подтверждает провідний | NONE |
| 6 | IC_PREPARATION → COMMERCIAL_TERMS_APPROVAL: система | Решение ІК и дата; при условном одобрении нужны условия | NONE |
| 7 | IC_PREPARATION → REFUSED: система | Решение ІК, дата, комментарий отказа, IC_NOT_APPROVED | CANCEL_ALL |
| 8 | COMMERCIAL_TERMS_APPROVAL → CONTRACT_APPROVAL: провідний, директор | Подтверждает CONTRACT_MANAGER | NONE |
| 9 | CONTRACT_APPROVAL → CONTRACT_SIGNED: провідний, директор, CONTRACT_MANAGER | Дата подписания и тип договора | NONE |
| 10 | CONTRACT_SIGNED → OPENED: провідний, директор | Фактическая дата открытия | NONE |
| 11 | Отказ с ІК и последующих этапов: провідний, директор | Причина | CANCEL_ALL |
| 12 | Один шаг назад, начиная с IC_PREPARATION: провідний, директор | — | CANCEL |
| 13 | REFUSED → FOUND / IN_PROGRESS / PAUSED: менеджер | Только после отказа до ІК | NONE |
| 14 | REFUSED → любой другой статус: провідний, директор | Для подписания и открытия сохраняются ограничения дат | NONE |
| 15 | Пауза до ІК: менеджер, провідний, директор | Сохраняется статус до паузы | NONE |
| 16 | Пауза после ІК: провідний, директор | Сохраняется статус до паузы | NONE |
| 17 | Снятие паузы: те же роли, что могут поставить её на этом этапе | Возврат именно в статус до паузы | NONE |

Правила «после ІК» включают OPENED: таблица разрешает отказ, паузу и шаг назад после поздних этапов. Флаг финальности OPENED сохранён; он обозначает успешный конец воронки, а доступные изменения определяются таблицей.

Снятие паузы в REFUSED имеет отдельное менеджерское правило с проверкой раннего происхождения отказа. Иначе менеджер мог бы обойти пункт 13 через паузу.

## Условия

| condition_code | Проверка сценария |
|---|---|
| RESUME_PREVIOUS_STATUS | Цель равна status_before_pause_id |
| EARLY_STATUS_BEFORE_PAUSE | Этап до паузы — FOUND или IN_PROGRESS |
| EARLY_STATUS_BEFORE_REFUSAL | Этап до отказа — FOUND или IN_PROGRESS |
| CONTRACT_STATUS_BEFORE_PAUSE | Этап до паузы — CONTRACT_APPROVAL, CONTRACT_SIGNED или OPENED |
| RESUME_EARLY_REFUSED | Этап до паузы — REFUSED и этап до отказа — FOUND или IN_PROGRESS |

Актуальные сиды не используют BLOCK; поддержка 422 для отдельно настроенного правила сохранена. CANCEL отменяет незавершённые задачи активного набора исходного статуса и уведомляет исполнителей. CANCEL_ALL отменяет все незавершённые задачи объекта. NONE задачи не изменяет. Здесь хранится конфигурация; выполнение переходов и уведомления — T6712, пауза задач — T6725. Миграция не добавляет SQL-триггеры изменения статуса или выдуманные шаблоны задач.

## Миграция и откат

Положительные решения ІК используют NONE. Отказ ІК по актуальной таблице T6712 использует CANCEL_ALL. Changeset `20261005-ic-transition-task-policy` сохраняет UUID, остальные параметры правил и существующие данные; его rollback возвращает прежний CANCEL. Версии и время изменения конфигурации обновляются. Миграция `20261015_status_task_policy` устанавливает актуальные действия и сохраняет предыдущую конфигурацию для отката без изменения объектов и задач. При rollback правило с более новой версией сохраняется.

Два новых changeset: `20261002_objects_transition_policy_schema` и `20261002_objects_transition_policy_seed`. Опубликованные SQL не меняются. UUID существующих справочников и переходов сохранены. Различающиеся права менеджера и руководства хранятся отдельными правилами.

Rollback двух changeset возвращает схему и конфигурацию 01.10: 47 правил, прежние роли и выключенные триггеры. Объекты, пользователи и существующие справочниковые UUID сохраняются. Новое поле этапа отказа удаляется; перед рабочим downgrade его данные необходимо резервировать. Версии и время изменения справочников монотонно обновляются. Ручное перенастраивание сидов перед downgrade не поддерживается: в MVP правила меняет команда отдельными миграциями.

Полная эталонная матрица: `src/test/resources/objects/t6712-transition-matrix.txt`. Проверки: ObjectTransitionPolicyIT, ObjectTransitionPolicyRollbackIT, прежние тесты модели и создания. Откат сравнивает столбцы, FK, CHECK, индексы, справочники и роли; повторное update не меняет UUID и число строк.

При отказе из паузы права определяются по этапу до паузы. Начиная с IC_PREPARATION отказ доступен только провідному и директору. ACTIVE-набор целевого статуса используется повторно без превью, нарезки и сообщения об отсутствующем шаблоне. COMPLETED и CANCELLED наборы позволяют новую нарезку.
