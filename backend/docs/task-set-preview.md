# Превью набора задач

`GET /api/objects/{id}/task-preview?status={code}` возвращает будущий состав набора по активному статусу-триггеру и текущему типу договора объекта. Например: `status=IN_PROGRESS`. Доступ нужен к полной карточке объекта: менеджеру по своим объектам, провідному по своим регионам, директору, CEO и администратору по сети.

Ответ содержит `templateId`, `revision`, `templateFound`, `triggerDate` и `tasks`. У задачи возвращаются название, срок, исполнитель и его имя, идентификаторы предшественников, необходимость проверки, роль и определённый пользователь — получатель результата. Предшественники ссылаются на `templateItemId` элементов этого же ответа.

Срок считается от `triggerDate` в календарных днях, включая выходные. Дата определяется в Europe/Kyiv. Зависимости не сдвигают срок. Просмотр относится к возможному переходу сегодня; при создании в другой день или после изменения объекта, шаблона либо пользователей план пересчитывается.

Календарное правило и смещение хранятся в элементе шаблона. Нулевое смещение возвращает срок в день перехода. Подробности: [расчёт сроков](task-deadlines.md).

Подбор шаблона и расчёт состава общие с фактическим созданием. Исполнитель выбирается по явному пользователю, менеджеру объекта, роли в регионе или роли по сети. Региональная иерархия и назначенные пользователю регионы учитываются. При нескольких подходящих исполнителях система не выбирает случайного пользователя.

Неопределённый исполнитель не удаляет элемент из превью: `assigneeId` и `assigneeName` равны null, а `assignment.issue` содержит `NOT_FOUND`, `INACTIVE`, `OUTSIDE_REGION` или `AMBIGUOUS`. У определённого исполнителя `assignment.issue=null`. Для получателя сохраняется настроенная роль; `resultRecipientId` заполняется, если найден один подходящий активный пользователь.

Отсутствующий, неактивный или пустой шаблон возвращает HTTP 200 с `templateFound=false`, `templateId=null`, `revision=""` и `tasks=[]`. Неоднозначная конфигурация шаблона или цикл зависимостей возвращают `409 TASK_TEMPLATE_CONFIGURATION_ERROR`.

Превью не сохраняет задачи, набор, редакцию шаблона, статус, историю, запрос согласования или событие уведомления. Чтение выполняется в согласованном снимке транзакции с разделяемыми блокировками записей шаблона. Ответ имеет `Cache-Control: no-store`. Ошибки доступа и входных данных используют обычный контракт API.

Создание по-прежнему требует подтверждения и повторной проверки плана. Неопределённый исполнитель блокирует сохранение с 422. Созданный набор фиксирует правила назначения, зависимости и параметры проверки в неизменяемой редакции; задачи получают рассчитанных исполнителей, сроки и получателей результата.

Миграция `20261020_task_preview` добавляет правила назначения и зависимости в редактируемые элементы шаблона. Существующие элементы остаются `EXPLICIT_USER`. Откат возвращает прежнюю схему, если нет новых правил и зависимостей; иначе он останавливается, чтобы не потерять настройки.

Спецификация: [OpenAPI](openapi/task-set-preview.yaml).

Подтверждение и асинхронное создание описаны в [контракте T5808](task-set-generation.md).
