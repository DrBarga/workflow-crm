T5805. Источники: Бізнес вимоги v3 §6.2 и актуальные критерии задачи с уточнениями от 21.10.2026.

В начальной матрице два общих шаблона без типа договора: `IC_PREPARATION` («Підготовка на ІК») и `CONTRACT_APPROVAL` («Погодження договору»). Для остальных статусов сид не создаёт шаблоны. Подбор точной пары и переход к общему шаблону описаны в [правилах подбора](task-template-selection.md).

Эскалация всех семи элементов — один день. Дни календарные, срок считается от фактической даты перехода; ожидание предшественника не меняет срок. Сид сохраняет настройку эскалации; отправка напоминаний относится к Notifications & Escalations.

Для менеджера используется `OBJECT_MANAGER`, для провідного — `REGIONAL_ROLE` с ролью `REGIONAL_MANAGER`, для договорного отдела — `NETWORK_ROLE` с ролью `CONTRACT_MANAGER`. Сид хранит правила и роли, без привязки к конкретным сотрудникам и окружению.

## Загрузка и замена данных

Исходные четыре задачи ІК остаются в опубликованной миграции `20261021_ic_preparation_template`. Миграция `20261027_task_template_matrix` добавляет им эскалацию и загружает договорной шаблон. Применённые changeset не редактируются.

Договорная матрица находится в `20261027_contract_template_matrix.sql`. Общий загрузчик состоит из двух файлов:

- `seed/template_matrix_stage.sql` создаёт временные таблицы определений, элементов и зависимостей;
- `seed/template_matrix_apply.sql` проверяет данные и переносит их в рабочие таблицы.

В определении задаются UUID, код статуса и необязательный код типа договора. В элементе — стабильный UUID, название, срок, порядок, правило назначения, пользователь или роль, проверка, получатель и эскалация. Зависимости связывают UUID элементов одного шаблона. Для типовой пары записываются ссылка на справочник и его код для совместимости с прежней схемой.

Перед сохранением проверяются статусы, типы договора, пользователи, роли, непустой состав, параметры назначения и отсутствие циклов, включая зависимость от себя. Внешние ключи временных таблиц запрещают неизвестных предшественников и связи между шаблонами. Ошибка прерывает changeset, шаблон и его части не сохраняются. Временные таблицы удаляются при завершении транзакции.

Следующая согласованная матрица оформляется новым файлом данных и changeset с тем же загрузчиком. Названия, сроки, роли и зависимости не требуют изменений Java. UUID прежних элементов сохраняются; обновление уже существующего шаблона оформляется отдельной миграцией с проверкой исходных данных. Загрузчик не перезаписывает рабочие настройки автоматически.

## Обновление и откат

Существующий общий договорной шаблон, в том числе неактивный, сохраняется целиком. Шаблоны отдельных типов договора не заменяются общим. Эскалация ІК обновляется только у неизменённого стандартного шаблона: проверяются его версия, состав, параметры и единственная зависимость. Пользовательские изменения не исправляются поверх.

Повторное применение changelog не создаёт дублей. Откат удаляет только созданный договорной шаблон и возвращает прежнюю настройку эскалации ІК. Если changeset был пропущен из-за пользовательского шаблона, откат его не затрагивает. Откат договорной матрицы останавливается, если шаблон уже редактировался или использовался для сохранения редакции; существующие наборы и их история не удаляются. Откат эскалации также останавливается, если её версия изменилась после миграции.

`TaskTemplateMatrixSeedIT` проверяет свежую установку, повторное применение, откат, пользовательские шаблоны, ошибочные назначения, справочники, циклы и замену входной матрицы. `TaskTemplateMatrixGenerationIT` проверяет превью и создание обоих наборов с реальными правилами назначения и сроков.
