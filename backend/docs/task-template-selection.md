# Подбор шаблона задач

Подбор используется переходами статуса, изменением дат этапов, согласованием перехода и решением ІК через публичный API `ObjectTaskTransition`.

## Правила выбора

Шаблон выбирается по статусу-триггеру и типу договора объекта. Учитываются только активные записи `task_templates`. По решению Влада от 21.10.2026 сначала проверяется точная пара; если подходящий шаблон отсутствует, неактивен или пустой, используется общий шаблон этого статуса. Если тип отсутствует или пустой, выбирается общий шаблон. При отсутствии обоих вариантов переход выполняется без задач.

| Шаблон точной пары | Общий шаблон статуса | Результат |
|---|---|---|
| Активный с элементами | Любой | Точная пара |
| Отсутствует, неактивен или пустой | Активный с элементами | Общий шаблон |
| Отсутствует, неактивен или пустой | Отсутствует, неактивен или пустой | Шаблона нет |
| Несколько активных записей одной пары | Любой | Ошибка конфигурации |

Пустой состав не скрывает дубли точной пары: неоднозначность проверяется до перехода к общему шаблону. Шаблон другого типа договора не используется как запасной.

`contract_type_id` ссылается на общий справочник T5770 и имеет приоритет над историческим текстовым полем. Для прежних шаблонов поддерживаются код и название типа из того же справочника. Например, `PRIMARY`, «Основний» и ссылка на соответствующую запись обозначают одну пару, а не три разных конфигурации. При смене типа договора прежний текст объекта не участвует в выборе.

Актуальным определением является текущее состояние активного шаблона и его элементов, прочитанное под разделяемой блокировкой. `TaskTransitionPlan.revision` учитывает версии этих записей. Исторические `task_template_versions` фиксируют уже созданные наборы и не заменяют текущий черновик при подборе. Их содержимое не изменяется.

## Отсутствие и неоднозначность

Отсутствующий, неактивный или пустой шаблон даёт пустой план с `templateId=null`, `tasks=[]` и `missingTemplate()=true` в API Tasks. Получение плана не создаёт набор, редакцию шаблона или событие уведомления. HTTP-контракт перехода сохраняется: успешный переход без задач возвращает `saved=true`, `confirmationToken=null`, пустой список задач.

После фактического сохранения перехода существующий сценарий Objects в одной транзакции записывает отсутствие шаблона в историю, аудит и `event_outbox` с типом `OBJECT_TASK_TEMPLATE_MISSING`. Уведомление ставится активным пользователям SUPERADMIN. При ошибке записи события переход и уведомления откатываются. Повторный запрос с прежней версией объекта не создаёт повторное событие. Доставка email и Telegram относится к Notifications & Escalations.

Если одной паре соответствуют несколько активных записей, возвращается `409 TASK_TEMPLATE_CONFIGURATION_ERROR` с `Cache-Control: no-store`. Это относится и к сочетаниям старого текстового и нового ссылочного формата. Более новая версия или непустой состав одного из дублей не устраняют неоднозначность: переход, решение ІК и создание набора не выполняются, пока конфигурация не исправлена.

Подбор не меняет настройки шаблонов, справочник договоров, правила отмены задач и права перехода. Дополнительная миграция для этого сценария не требуется.

## Подтверждение выбранного набора

Превью и подтверждённый переход используют один порядок подбора. Если между ними появился шаблон точной пары или прежний точный шаблон стал пустым, старое подтверждение отклоняется с `409`: статус, задачи и события не изменяются. Пользователь получает новое превью и подтверждает актуальный набор.

`TaskTemplateFallbackIT` проверяет все 16 сочетаний состояния точного и общего шаблонов через HTTP-превью, переход и сохранённую версию набора. Там же проверяются смена выбранного шаблона перед подтверждением и дубли пустой точной пары. `TaskTemplateSelectionIT` покрывает отсутствие типа и совместимость со справочником, `TaskTemplateTransitionIT` — уведомление об отсутствии шаблона и откат при ошибке outbox.
